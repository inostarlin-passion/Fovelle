## 2. 基线失败与根因

### 2.1 WebP 方向回归

[Build Fovelle run 32107116589](https://github.com/inostarlin-passion/Fovelle/actions/runs/32107116589) 的失败日志为：

```text
ImageLoaderTests::testImageLoaderAppliesWebpOrientation() Compared values are not the same
Actual (result->image.size()): QSize(2x3)
Expected (QSize(3, 2)): QSize(3x2)
```

同期的 [Checks run 32107116541](https://github.com/inostarlin-passion/Fovelle/actions/runs/32107116541) 的单元 job 也报告同一断言失败。源码审计发现旧流程是“先 Qt，Qt 仅在空图时才 ImageIO”。这解释了为什么 native ImageIO 的直接断言可以通过，而 loader 结果仍是未旋转尺寸。这里“Qt 返回非空但方向未处理”是基于日志和源码控制流的推断，不是 CI 内部插件状态的直接打印事实。

### 2.2 clang-tidy 失败

同一 Checks run 的 clang-tidy job 结尾为：

```text
Error: no checks enabled.
```

workflow 已安装 LLVM，并通过 `CMAKE_CXX_CLANG_TIDY=clang-tidy` 调用工具，但修复前没有 `.clang-tidy` 的启用项。依据 [LLVM clang-tidy 官方文档](https://clang.llvm.org/extra/clang-tidy/index.html)，检查集合需要由 `-checks` 或配置文件提供，因此该失败是配置缺失，而不是源文件诊断失败。

## 3. 实施内容

### 3.1 生产代码

在 [`src/qvimageloader.cpp`](../src/qvimageloader.cpp) 中：

- 根据文件后缀和 `supportsAdditionalImageFormat()` 判断是否使用 macOS ImageIO。
- WebP/AVIF 先调用 `QVCocoaFunctions::readAdditionalImage()`，使 Apple ImageIO 的方向变换真正成为 loader 主路径。
- ImageIO 失败时仍调用 `QImageReader`，保留有限且明确的 fallback。
- 其他格式的 SVG、动画、多帧选择逻辑保持原有路径。

Apple 文档确认 [`kCGImageSourceCreateThumbnailWithTransform`](https://developer.apple.com/documentation/imageio/kcgimagesourcecreatethumbnailwithtransform?changes=__5) 会让缩略图符合图像方向和宽高比；Qt 的 [`QImageReader`](https://doc.qt.io/qt-6/qimagereader.html) 自动变换能力仍保留在 fallback reader 上。

### 3.2 CI 配置与质量门禁

新增 [`.clang-tidy`](../.clang-tidy)：

```yaml
Checks: >-
  -*,
  bugprone-use-after-move,
  performance-move-const-arg,
  clang-diagnostic-*
WarningsAsErrors: ''
HeaderFilterRegex: '(^|/)(src|tests)/'
FormatStyle: file
```

[`tests/quality_static.py`](../tests/quality_static.py) 新增 ST-18，检查配置、workflow LLVM 安装和 `build.sh --tidy` wiring；[`tests/quality_integration.py`](../tests/quality_integration.py) 新增 I-15，在本机可用 clang-tidy 时执行 `--verify-config`。

## 6. 事实、推断、不确定性和剩余风险

| 类别 | 结论 |
|---|---|
| 事实 | 本地 Qt 6.11.1/Cocoa/arm64 的静态、单元、集成、系统证据全部通过；方向断言由真实测试二进制执行。 |
| 事实 | clang-tidy 配置验证返回 0，且本地 `./build.sh --tidy` 返回 0。 |
| 推断 | ImageIO-first 直接消除了旧流程中“Qt 非空结果阻断 ImageIO”的控制流缺口。 |
| 不确定性 | 本地环境不是失败 run 的 Qt 6.8.x/macOS 14；修复后的远程 runner 尚未因本次工作区没有推送提交而重跑。 |
| 不确定性 | 未在本地执行 GitHub runner 的完整网络环境、缓存和安装动作；workflow 文件静态契约已验证。 |
| 剩余风险 | clang-format 版本会影响格式诊断；基线的 GitHub clang-format job 已通过，但修复提交仍应在同一 runner 上复跑全 workflow。 |

测试规格书中的 TC-CI-WEBP-ORI、TC-CI-AVIF-ORI、TC-CI-NATIVE-DECODER、TC-CI-TIDY-CONFIG、TC-CI-STATIC、TC-CI-UNIT、TC-CI-INTEGRATION、TC-CI-SYSTEM、TC-CI-PERFORMANCE 均逐项固定以下字段，并由对应测试代码和 JSON 证据支撑：

| 字段 | 审计含义 |
|---|---|
| 测试目的 | 要证明的单一原子行为 |
| 前置条件 | 构建、平台、工具和运行状态 |
| 输入数据 | fixture、源码配置、二进制或负载参数 |
| 操作步骤 | 可重复执行的命令和观测动作 |
| 预期结果 | 精确尺寸、返回码、计数或性能阈值 |
| 后置条件 | 进程、临时文件、配置和证据的清理/保留要求 |
