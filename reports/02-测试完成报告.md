## 1. 实现完成情况

### 1.1 小图片 1:1 选项

- 在 [`src/settingsmanager.cpp`](../src/settingsmanager.cpp) 注册 `smallimageoneone`，默认关闭，避免改变既有用户行为。
- 在 [`src/qvoptionsdialog.ui`](../src/qvoptionsdialog.ui) 的 Settings → Image 增加 `Show small images at 1:1`。
- 在 [`src/qvoptionsdialog.cpp`](../src/qvoptionsdialog.cpp) 完成配置绑定和 Apply 持久化。
- 在 [`src/qvgraphicsview.cpp`](../src/qvgraphicsview.cpp) 使用实际 `getUsableViewportRect()`，仅当开关打开、Window matches image size 为 Never 且图片宽高均严格小于 viewport 时，将自动 ZoomToFit/FillWindow 的目标比例设为 1.0；Original Size 本身已是 1.0。
- 打开图片和浏览图片共用 `postLoad()` → `fitOrConstrainImage()` 链路；新增测试已覆盖首次打开与 Next 切换。

### 1.2 Issue #864 风险处理

[`src/mainwindow.cpp`](../src/mainwindow.cpp) 现执行以下生命周期约束：停止 Open With 定时器；同一窗口只允许一个 worker，后续刷新排队；文件路径按值捕获；只接受仍对应当前文件的结果；析构时对正在运行的 `QFutureWatcher` 调用 `waitForFinished()`。该实现对应 [Issue #864](https://github.com/jurplel/qView/issues/864) 描述的 QtConcurrent/QPixmap teardown 风险。Issue 与本项目代码的对应关系属于基于代码结构的推断，已由 Cocoa 独立进程测试验证行为。

### 1.3 Tag Release

新增 [`.github/workflows/release.yml`](../.github/workflows/release.yml)：

- `push.tags` 使用 `v*`；
- macOS runner 构建 app，并先运行 CTest；
- 使用 `ditto` 生成 `Fovelle-<tag>-macOS.zip`；
- 以 `contents: write` 和 `GITHUB_TOKEN` 调用 `softprops/action-gh-release@v3`，自动生成 Release Notes 并上传 zip。

本地没有推送 tag，也没有调用 GitHub Release API；因此“真实云端 Release 已创建”不是本报告声称的事实，已验证的是工作流静态/集成契约。
