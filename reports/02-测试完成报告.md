## 2. 实现结果与验收结论

### 2.1 本次差异的根因与修复

根因已定位到应用自绘背景：`MainWindow::settingsUpdated()` 原先把 Light Theme 的 `customBackgroundColor` 设置为白色，随后 `paintEvent()` 直接使用该成员填充画面留白；原生 Aqua 标题栏不会自动改变这段 Qt 自绘区域。用户提供的 Preview 截图留白区域采样为 `(150,150,150)`，即 `#969696`。

修复将 Light Theme 画面背景改为 `QColor("#969696")`，保留 Aqua 标题栏、Dark Theme 的 `#212121` 和棋盘格优先级，并由 `WindowBehaviorTests::testThemeAppliesNativeAppearanceAndViewportBackground` 精确回归。

## 5. 异常与重跑说明

在正式系统门禁前曾尝试并行启动多个 Cocoa 测试进程，因共享桌面焦点/全屏状态产生一次 `isActiveWindow()` 假失败和 SIGSEGV；同一批次的标题栏回归仍通过。按 Cocoa 测试的共享状态约束改为串行执行后，功能、全屏、标题栏和资源探针均稳定通过。该并行试验不作为最终证据，最终 JSON 已由串行命令覆盖。

这一区分是环境并发事实，不推断为产品运行时崩溃；若 CI 需要并行，应为每个 Cocoa 测试分配独立桌面/会话或保持串行。

## 6. 证据与限制

- 事实：最终证据 JSON 中所有 `pass` 标志为 true，QtTest 总失败/跳过/黑名单为 0。
- 事实：用户提供的 Preview 截图中主体留白区域采样为 RGB `(150,150,150)`，即 `#969696`；当前 Light Theme 原先错误地使用 `QColorConstants::White`。
- 推断：A/B/C/D 的主题映射采用 Aqua/DarkAqua 与 `#969696`/`#212121` 的稳定实现；`#969696` 是该截图的参考色，不推断为所有 macOS/Preview 设置的全局固定值。
- 限制：没有可审计的 Preview 当前窗口截图和固定 RGB 基线，因此本次系统测试没有宣称逐像素证明 Preview 的 C/D；若产品验收要求精确像素等价，需要补充固定 macOS 版本、Preview 设置和参考截图/采样文件。
- Apple 外观依据：[Aqua](https://developer.apple.com/documentation/appkit/nsappearance/name-swift.struct/aqua?language=objc)、[Dark Aqua](https://developer.apple.com/documentation/appkit/nsappearance/name-swift.struct/darkaqua?language=objc)、[显式选择 App 外观](https://developer.apple.com/documentation/AppKit/choosing-a-specific-appearance-for-your-macos-app)。
