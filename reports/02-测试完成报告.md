## 2. 历史 Release 根因证据

### 2.1 workflow 成功不代表产物可信

历史 [Release run 32113103430](https://github.com/inostarlin-passion/Fovelle/actions/runs/32113103430) 的 job 成功，但日志中的关键步骤只有：

```text
Image: macos-14-arm64
Run cmake -S . -B build -DBUILD_TESTS=ON ...
Run ditto -c -k --sequesterRsrc --keepParent build/Fovelle.app ...zip
```

没有 Universal 架构参数，也没有 `macdeployqt`、`codesign`、`notarytool`、`stapler` 或 `spctl` 步骤。GitHub Actions 只验证了“命令成功生成并上传 zip”，没有验证用户可信任的 macOS distribution artifact。

### 2.2 已下载并检查旧资产

旧资产 [Fovelle-v0.1.0-macOS.zip](https://github.com/inostarlin-passion/Fovelle/releases/download/v0.1.0/Fovelle-v0.1.0-macOS.zip) 的本地审计结果：

| 检查 | 结果 |
|---|---|
| zip 大小 | 约 3.7 MiB |
| 解压 app 大小 | 约 6.0 MiB |
| 主二进制 | `Mach-O 64-bit executable arm64` |
| `lipo -info` | thin `arm64` |
| CodeDirectory | `adhoc,linker-signed` |
| Developer ID Authority | 不存在 |
| TeamIdentifier | `not set` |
| Qt framework | `Contents/Frameworks` 不存在；主程序依赖 `@rpath/Qt*.framework` |
| Gatekeeper | `code has no resources but signature indicates they must be present` |

因此根因是三个独立缺口叠加：单架构、自包含部署缺失、正式签名/公证缺失。Apple 文档明确要求外部分发使用 Developer ID、Hardened Runtime、时间戳并完成 notarization；详见 [分发签名](https://developer.apple.com/documentation/xcode/creating-distribution-signed-code-for-the-mac/)、[公证](https://developer.apple.com/documentation/security/notarizing-macos-software-before-distribution?changes=_5)。

## 3. 实施修复

### 3.1 Universal

[`.github/workflows/release.yml`](../.github/workflows/release.yml) 的 Configure 步骤增加：

```text
-DCMAKE_OSX_ARCHITECTURES="x86_64;arm64"
```

该顺序与 Qt 官方 Universal 示例一致。发布资产名改为 `Fovelle-<tag>-macOS-universal.zip`。

### 3.2 Qt 运行时部署和产物验证

新增 [`dist/scripts/package-macos-release.sh`](../dist/scripts/package-macos-release.sh)：

- 使用 `QT_ROOT_DIR/bin/macdeployqt` 部署 Qt framework/plugin。
- 对 app 内所有 Mach-O 执行 `lipo -archs`，拒绝 thin 文件。
- 对最终 zip 解压后的 app 再重复检查，保证检查对象就是上传对象。

### 3.3 Developer ID 签名和 Apple 公证

脚本使用临时 keychain 导入 `APPLE_CERTIFICATE_BASE64`，通过 `security find-identity` 只接受 `Developer ID Application:` 且 Team ID 匹配的身份；随后：

1. 由内向外签名，包含 `--timestamp` 和 `--options runtime`。
2. `codesign --verify --deep --strict` 验证签名、Authority、Hardened Runtime 和时间戳。
3. `xcrun notarytool submit --wait` 提交公证。
4. `xcrun stapler staple/validate` 写入并验证 ticket。
5. `spctl --assess --type execute --ignore-cache` 验证 Gatekeeper。
6. 生成 zip 后解压，重复 `codesign`、`stapler`、`spctl` 验证。

GitHub workflow 显式传入五个已配置 Secret 名称，仓库没有写入 Secret 值。GitHub 官方说明 Secret 必须显式作为 workflow 环境变量或 input 使用，见 [GitHub Actions Secrets](https://docs.github.com/en/actions/concepts/security/secrets)。
