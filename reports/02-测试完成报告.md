# Fovelle 测试完成报告

## 1. 完成结论

本次单元、集成、系统三层测试均已按“单元 → 集成 → 系统”顺序执行并通过。合并提交为 `1be85e129e5ed06d6760cf9dadf9fc68fb61cbf1`，当前工作树头为 `3d3be0fcb39fb8f2e685fe999053daac89d26f00`。

结论的边界是：自动化证据证明了代码可追溯、可编译、事件队列/预加载器/色彩转换/QVMovie 基本行为正确，以及 bundle 的启动和资源代理满足本次测试门槛；Finder 手工菜单、真实 Dock UI、多帧 ICC/APNG 像素级比对、第三方 Open With 应用交互和签名公证没有在本机自动化执行，因此不把它们表述为已完成的端到端事实。

## 5. 系统测试结果

执行命令：

```text
python3 tests/quality_system_probe.py \
  --app build-quality-final/Fovelle.app/Contents/MacOS/Fovelle \
  --image dist/mac/qView.icns --runs 5 --hold-seconds 0.8 \
  --output reports/evidence/system.json
```

### 5.1 时间行为

| 指标 | 实测值 | 本地代理门槛 | 结果 |
|---|---:|---:|---|
| 启动平均 | `0.006742 s` | ≤ `2 s` | 通过 |
| P99 | `0.012091 s` | ≤ `3 s` | 通过 |
| 最大 | `0.012091 s` | ≤ `5 s` | 通过 |
| 吞吐 | `1.18337 runs/s` | ≥ `0.5 runs/s` | 通过 |

这些指标测量的是进程首次可见时间和 5 次启停吞吐，是系统级启动代理；图片像素解码正确性由单元测试中的异步 imageReady/图片加载断言覆盖。门槛数值是推断，因为需求没有提供数值规格。

### 5.2 资源利用

| 指标 | 实测峰值/值 | 本地代理门槛 | 结果与边界 |
|---|---:|---:|---|
| 进程 CPU（原始） | `101.2%` | 归一化 ≤ `100%` | 归一化为 `8.433%`，通过 |
| 逻辑 CPU 数 | `12` | — | 用于归一化，事实 |
| RSS | `287712 KiB`，约 `281 MiB` | ≤ `512 MiB` | 通过 |
| 句柄 | `104` | ≤ `512` | 通过 |
| 进程网络 socket | `0` | ≤ `4` | 通过 |

CPU、RSS、句柄和 socket 是进程级采样；`iostat`、`netstat` 与磁盘空间是主机级观测，可能包含无关后台活动。这一限制已写入 `system.json`，因此没有把主机计数伪装成应用精确 I/O。

### 5.3 系统生命周期

5/5 次真实 `Fovelle.app` 启动均出现进程、stderr 为空，并在探针发送 SIGTERM 后回收。探针返回码 `-15` 是测试主动终止的预期结果，不是应用启动失败；脚本把“启动成功”和“可控清理”作为独立断言。

## 7. 迭代记录与残余风险

1. 直接 cherry-pick 单个色彩转换提交时发现其父提交依赖上游全新 loader/movie 架构，出现跨架构冲突；这证明逐个挑拣不能保持依赖闭包。
2. 一次 `-X theirs` 实验在 `qvapplication.cpp` 形成重复构造逻辑，已废弃，没有进入最终树。
3. 最终采用“以完整上游头为第二父、保留本项目第一父并明确恢复上游树”的双父合并；随后补回 Fovelle bundle 名称、CMake、Launch Services 队列和测试。
4. 集成 runner 初版将 shell `grep` 误作为 `git grep` 调用，导致 I-04 假失败；已修正并在最终 JSON 中复跑全绿。这是测试基础设施迭代，不是产品代码失败。

残余风险集中在 macOS 原生 UI/外部服务边界：Finder 菜单、Dock UI、Open With 第三方 app、真实插件下载、代码签名/公证和多帧带 ICC profile 的视觉等价性仍需要人工或专用设备/账号回归。
