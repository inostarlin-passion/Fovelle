# 全屏快捷键与 macOS 全屏退出跳变测试完成报告

**文档编号**：TR-FS-2026-08-17
**规格书**：[01-测试规格说明书.md](01-测试规格说明书.md)
**执行日期**：2026-08-17（Asia/Shanghai）
**最终结论**：通过；真实物理键盘和逐帧 UI 动画仍属于人工补充验收范围。

## 1. 变更摘要

- 在 `MainWindow` 中增加主键 Enter（`Qt::Key_Return`）和小键盘 Enter（`Qt::Key_Enter`）两个非重复快捷键。
- 两个 Enter 快捷键共用“仅当当前不是全屏时进入全屏”的入口逻辑；全屏时重复按 Enter 不会退出。
- 删除全屏退出分支中先调用普通态 API 再恢复存储状态的重复请求，只保留一次 `setWindowState(storedWindowState)`。
- 增加四个行为测试、静态检查 runner、全屏系统 runner 和可审计 JSON 证据。

## 2. 根因与修复验证

### 事实

基线源码在退出全屏时同时请求 `showNormal()` 和 `setWindowState(storedWindowState)`；Qt Cocoa 实现对原生退出全屏等待通知，说明该转换存在异步窗口。上游历史 [`6e5297d`](https://github.com/inostarlin-passion/Fovelle/commit/6e5297df9602e391c3b8b001f4f83ef7ca0f711d) 也曾删除同一位置的 `showNormal()`。当前代码已改为只请求一次存储状态。

### 推断

“Esc 跳变、点击左上角按钮正常”最符合重复状态请求与 Cocoa 异步过渡重叠的解释。集成结构检查确认退出分支只有一个恢复请求；TC-FS-04 进一步确认图片路径、可见性和进入前几何均恢复。

### 不确定性

测试没有通过 Accessibility 控制真实的 macOS 左上角按钮，也没有采集动画逐帧截图；`FS_METRIC` 代表 Qt 状态确认时间，不能等同于动画完成时间。
