# 全屏快捷键与 macOS 全屏退出跳变测试规格说明书

**文档编号**：TS-FS-2026-08-17
**版本**：1.0
**被测项目**：Fovelle 0.1.0（macOS）
**执行顺序**：静态检查 → 单元测试 → 集成测试 → 系统测试
**规格状态**：可执行、可审计

## 1. 目的与范围

本规格书覆盖两项需求：

1. 普通窗口中按主键 Enter 或小键盘 Enter 进入全屏。
2. 打开图片后执行“普通窗口 → 全屏 → Esc 退出”时，窗口内容和几何状态不再跳变。

同时把“精益完整性、功能正确性、时间行为、资源利用、可测试性”拆成可判定的原子验收标准，并为每条标准配置测试用例和可执行测试代码。测试只涉及本次全屏行为，不扩大到无关的产品功能。

## 2. 根因分析与可验证依据

### 2.1 事实

- 本次修改前，`MainWindow::toggleFullScreen()` 的退出分支连续调用 `showNormal()` 和 `setWindowState(storedWindowState)`；本地 Git 历史还保留了上游提交 [`6e5297d remove shownormal`](https://github.com/inostarlin-passion/Fovelle/commit/6e5297df9602e391c3b8b001f4f83ef7ca0f711d)，该提交删除了同一退出分支中的 `showNormal()`。
- Qt 文档说明 `QWidget::showFullScreen()` 在 macOS 上把应用置入专用全屏桌面；Qt 同时说明 `QWindow::showFullScreen()` 等价于设置 `Qt::WindowFullScreen` 后显示，而 `showNormal()` 等价于设置 `Qt::WindowNoState` 后显示：[QWidget::showFullScreen](https://doc.qt.io/qt-6/qwidget.html#showFullScreen)、[QWindow::showFullScreen](https://doc.qt.io/qt-6/qwindow.html#showFullScreen)、[QWindow::showNormal](https://doc.qt.io/qt-6/qwindow.html#showNormal)。
- Qt Cocoa 平台代码在应用窗口状态时调用原生 `NSWindow` 的全屏切换，并对退出全屏等待 `NSWindowDidExitFullScreenNotification`：[Qt Cocoa 窗口实现](https://github.com/qt/qtbase/blob/dev/src/plugins/platforms/cocoa/qcocoawindow.mm#L3573-L3690)。这证明退出不是可以安全地在同一时刻叠加多个状态请求的同步普通窗口切换。
- Apple 文档定义 `NSWindow.toggleFullScreen(_:)` 为“将窗口带入或带出全屏”：[Apple `toggleFullScreen(_:)`](https://developer.apple.com/documentation/appkit/nswindow/togglefullscreen%28_%3A%29)。
- Qt 文档说明 `QShortcut::activated()` 在快捷键序列完成时发出：[QShortcut](https://doc.qt.io/qt-6/qshortcut.html)。Qt 将主键 Enter 与小键盘 Enter 分别表示为 `Qt::Key_Return` 和 `Qt::Key_Enter`：[Qt Key 枚举](https://doc.qt.io/qt-6/qt.html#Key-enum)。

### 2.2 推断

- 最可能的根因是状态请求重复：第一次 `showNormal()` 已经启动 Cocoa 的退出全屏过渡，随后 `setWindowState(storedWindowState)` 又在原生过渡尚未完成时请求恢复状态。重复请求会让 Qt/Cocoa 在过渡期间重新应用窗口几何，从而表现为内容跳变。
- 点击 macOS 窗口左上角退出全屏时，AppKit 只发起一次原生状态变化，因此没有第二个 Qt 状态请求；这与用户观察到“点击按钮正常、Esc 跳变”相符，但这部分是基于源码路径和现象的因果推断。
- 修复策略是退出分支只调用一次 `setWindowState(storedWindowState)`；Enter 使用两个非重复快捷键，并只在当前不是全屏时调用进入逻辑，使入口具有幂等性。

### 2.3 不确定性与边界

- 测试测量的是 Qt 报告目标状态的确认时间，不是 macOS 全屏动画每一帧的完成时间；动画时长仍可能受 macOS 版本、显示器和系统负载影响。
- 自动化使用 `QTest::keyClick()` 和 `QShortcut::activated`，不需要人工键盘或 Accessibility 权限；未自动化点击真实的 macOS 左上角按钮，也未做逐帧截图比较，因此最终人工验收仍应检查一次真实 UI。
- 用户没有提供具体的性能和资源 SLO。下列数值是本次验收用的工程门槛，是测试推断，不应解释为生产 SLA。

## 4. 测试环境、输入和门槛

### 4.1 环境

- macOS 15.7.7，arm64；Qt 6.11.1；CMake 4.4.0；Python 3.14.6。
- 仓库：`/Users/inostarlin/code/Fovelle`；构建目录：`build-fovelle-task`。
- 构建参数：`-DBUILD_TESTS=ON -DFOVELLE_BUILD_TRANSLATIONS=OFF -DQV_DISABLE_ONLINE_VERSION_CHECK=ON`。
- Qt 测试环境：`QT_QPA_PLATFORM=cocoa`、`QT_FATAL_WARNINGS=1`。
- 图片输入：每个图片用例在 `QTemporaryDir` 中生成确定性的 32×32 PNG，不依赖用户文件或网络。

### 4.2 全屏状态响应门槛

| 指标 | 门槛 | 观测定义 |
|---|---:|---|
| 平均响应时间 | ≤ 2000 ms | 从合成快捷键/shortcut 请求到 Qt 报告目标全屏状态 |
| P99 响应时间 | ≤ 2000 ms | 7 个 Enter/Esc 状态确认样本的离散 P99 |
| 最大响应时间 | ≤ 2000 ms | 同一批样本最大值 |
| 状态确认吞吐率 | ≥ 0.5 次/s | 状态确认样本数 ÷ 样本响应时间总和 |

### 4.3 App 启动和资源门槛

系统探针以 5 次独立 App 进程启动、打开同一 PNG 并保持 0.8 s 为目标负载。门槛如下：

| 指标 | 门槛 | 观测工具 |
|---|---:|---|
| 启动平均/P99/最大值 | ≤ 2.0/3.0/5.0 s | `ps` 采样启动时刻 |
| 启动吞吐率 | ≥ 0.5 次/s | 5 次启动总耗时 |
| 进程 CPU（按逻辑 CPU 归一化） | ≤ 100% | `ps` |
| 进程 RSS | ≤ 524288 KiB | `ps` |
| 磁盘空间使用率 | ≤ 95% | `shutil.disk_usage` |
| 主机磁盘 I/O | ≤ 500 MB/s | `iostat` |
| 主机网络字节增量 | ≤ 64 MiB/本轮 | `netstat -ib` |
| 进程打开句柄 | ≤ 512 | `lsof -p` |
| 进程网络 socket | ≤ 4 | `lsof -a -i` |

## 5. 原子测试用例设计

以下每个用例均明确包含测试目的、前置条件、输入数据、操作步骤、预期结果和后置条件；TC-FS-01～04 的同名注释和断言已固化在 [`tests/tst_qviewtests.cpp`](../tests/tst_qviewtests.cpp) 中。

### TC-FS-01：主键 Enter 进入全屏

- **测试目的**：验证普通窗口中的 `Qt::Key_Return` 能进入全屏。
- **前置条件**：`MainWindow` 可见、激活、非全屏；临时 PNG 已加载；应用退出策略临时关闭。
- **输入数据**：确定性 PNG、`Qt::Key_Return`。
- **操作步骤**：创建窗口并设为 `Qt::WindowNoState`；`show/raise/activateWindow`；打开 PNG；确认加载完成和非全屏；调用 `QTest::keyClick`；等待全屏；等待 2 s 让 Cocoa 过渡稳定；发送 Esc 清理。
- **预期结果**：窗口在 2 s 内变为全屏；退出清理成功。
- **后置条件**：关闭窗口，恢复原 `quitOnLastWindowClosed` 值。

### TC-FS-02：小键盘 Enter 进入全屏

- **测试目的**：验证 `Qt::Key_Enter` 与主键 Enter 具有相同的进入行为。
- **前置条件**：同 TC-FS-01，且窗口已激活。
- **输入数据**：确定性 PNG、`Qt::Key_Enter`。
- **操作步骤**：创建并激活非全屏窗口；加载 PNG；调用 `QTest::keyClick(&window, Qt::Key_Enter)`；等待并记录进入响应；等待 Cocoa 稳定；发送 Esc 清理。
- **预期结果**：窗口在 2 s 内进入全屏；记录到 `FS_METRIC enter_ms` 和 `exit_ms`。
- **后置条件**：关闭窗口并恢复退出策略。

### TC-FS-03：全屏时 Enter 幂等

- **测试目的**：验证 Enter 只负责进入，不会把全屏窗口切回普通窗口。
- **前置条件**：可见、激活的 `MainWindow` 已调用 `showFullScreen()`，并等待 Qt 全屏状态和原生过渡稳定。
- **输入数据**：依次为 `Qt::Key_Return`、`Qt::Key_Enter`。
- **操作步骤**：发送两个 Enter；处理事件 100 ms；读取 `isFullScreen()`；发送 Esc 退出。
- **预期结果**：两次 Enter 后仍为全屏，未启动退出状态变化。
- **后置条件**：窗口退出全屏、关闭并恢复退出策略。

### TC-FS-04：加载图片后 Esc 恢复内容和几何

- **测试目的**：复现“图片已打开、Enter 进入全屏、Esc 退出”的回归场景，并验证不跳变。
- **前置条件**：可见、激活、非全屏窗口已加载临时 PNG；窗口几何被确定性设置为 `QRect(200, 200, 640, 480)`。
- **输入数据**：PNG、`Qt::Key_Return`，以及与 Esc 快捷键相同的 `QShortcut::activated` 信号。
- **操作步骤**：保存进入前几何和图片绝对路径；用 Enter 进入全屏并等待 2 s；校验 Esc shortcut；以 `Qt::DirectConnection` 触发该 shortcut；等待非全屏和几何恢复；再次校验图片路径、可见性和几何。
- **预期结果**：窗口可见且非全屏；图片绝对路径不变；几何等于进入前值；退出响应有 `FS_METRIC exit_ms`。这是同一产品分支的确定性触发，不声称模拟了物理键盘电气路径。
- **后置条件**：关闭窗口并恢复退出策略。

### TC-FS-05：单一恢复状态请求静态回归

- **测试目的**：验证修复没有重新引入重复状态请求。
- **前置条件**：工作区存在源码和已配置的构建目录。
- **输入数据**：`src/mainwindow.cpp` 的 `toggleFullScreen()` 源文本。
- **操作步骤**：运行 `python3 tests/quality_static.py ...`；检查 ST-04；运行集成 runner；检查 I-FS-02。
- **预期结果**：退出分支包含且只包含一次 `setWindowState(storedWindowState);`，不包含 `showNormal(`；测试源码包含 TC-FS-01～04。
- **后置条件**：只写入 JSON 证据，不修改源代码。

### TC-Q-01：静态门禁

- **测试目的**：验证 C++ 可编译、Python runner 可解析、差异无空白错误、全屏退出结构满足不变量。
- **前置条件**：macOS 构建目录可用；`tests/quality_static.py` 存在。
- **输入数据**：三份 C++ 文件、全部 `tests/quality_*.py`、当前 Git diff。
- **操作步骤**：运行 `quality_static.py`；当 `clang-format` 不在环境中时，使用同一脚本记录的 CMake 编译回退检查。
- **预期结果**：ST-01～ST-04 全部 `pass=true`，并写入 `reports/evidence/static.json`。
- **后置条件**：不改写源码；保留 JSON 作为静态检查审计记录。

### TC-Q-02：四阶段可重复执行

- **测试目的**：验证静态、单元、集成、系统均有明确入口、退出码和机器可读证据。
- **前置条件**：项目已构建；macOS Cocoa 会话可用；系统工具 `ps/lsof/iostat/netstat` 可用。
- **输入数据**：构建出的 `Fovelle.app`、`fovelle_tests`、确定性 PNG。
- **操作步骤**：按“静态 → 单元 → 集成 → 系统”的顺序运行四类 runner；检查每个 JSON 的 `kind`、`passed`、用例状态和输出尾部。
- **预期结果**：四类证据均为 `passed=true`；所有功能用例 TC-FS-01～04 均为 passed；无单元失败或跳过。
- **后置条件**：结束测试进程，保留 JSON；不依赖在线服务。

### TC-Q-03：全屏响应时间

- **测试目的**：验证 Enter 进入和 Esc 退出的平均、P99、最大响应时间及吞吐率。
- **前置条件**：已构建带 `FS_METRIC` 输出的测试二进制。
- **输入数据**：7 个由 TC-FS-01、02、04 以及 Esc 回归用例产生的状态确认样本。
- **操作步骤**：运行 `quality_fullscreen_system.py`；解析 `FS_METRIC enter_ms/exit_ms`；计算平均、离散 P99、最大值和状态确认吞吐率。
- **预期结果**：所有时间和吞吐门槛通过；结果写入 `reports/evidence/system-functional.json`。
- **后置条件**：测试进程正常退出；保留原始输出尾部和指标定义。

### TC-Q-04：App 启动与资源利用

- **测试目的**：在 5 次独立启动和打开图片的目标负载下验证 CPU、RSS、磁盘、网络、句柄、socket 与启动时间。
- **前置条件**：Bundle 可执行文件和 PNG 存在；系统采样工具可执行。
- **输入数据**：`Fovelle.app/Contents/MacOS/Fovelle`、`resources/Fovelle.png`、5 次运行、每次保持 0.8 s。
- **操作步骤**：运行 `quality_system_probe.py`；在进程级采样 CPU/RSS/句柄/socket，在主机级采样磁盘/网络计数器；比较门槛。
- **预期结果**：S-01～S-12 全部为 true；结果写入 `reports/evidence/system.json`。
- **后置条件**：每个被测 App 进程被有界终止；主机计数器不被写入或重置。
