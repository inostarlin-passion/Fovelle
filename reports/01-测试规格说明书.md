| 版本 | 1.0 |

## 2. 需求边界

### 2.1 必须满足

1. 主窗口不设置窗口级 App icon；加载图片后也不能由窗口级 icon 重新产生标题栏图标。
2. 主窗口不关联文档路径；加载图片后原生窗口的 `QWindow::filePath()` 必须为空，从而不显示 macOS document proxy icon。
3. 图片仍能加载，标题文字仍能显示文件名。
4. 重复加载文件、切换标题栏显隐状态后，上述两个状态仍保持清空，且不改变应用 bundle 的 Finder/Dock icon。
5. 在规定目标负载下满足时间、吞吐和资源门槛，并保留可重复、非侵入式观测手段。

### 2.2 不在本次范围

- 菜单项、上下文菜单、Open With 列表中的 action icon。
- `Info.plist` 中的 `CFBundleIconFile`、Finder/Dock icon 和图片文件关联；这些是应用身份，不是窗口标题栏状态。
- 标题文本内容、图片解码器和既有缩放逻辑的功能变更；它们只做回归验证。

## 3. 可验证依据与推导链

### 3.1 事实

1. Qt `QWindow::setIcon()` 文档说明：macOS 标题栏 icon 用于文档窗口，只有同时设置 file path 才会显示。[Qt QWindow::setIcon](https://doc.qt.io/qt-6/qwindow.html#icon-prop)
2. Qt `QWidget::windowFilePath` 文档说明：macOS 下设置文件路径会设置窗口的 proxy icon；没有文件路径时该属性为空。[Qt QWidget::windowFilePath](https://doc.qt.io/qt-6/qwidget.html#windowFilePath-prop)
3. Qt 源码中 `QWindow::setFilePath()` 将路径保存到 `QWindow` 并转发给平台窗口，`QWindow::setIcon()` 将 icon 转发给平台窗口。[Qt qwindow.cpp](https://raw.githubusercontent.com/qt/qtbase/dev/src/gui/kernel/qwindow.cpp)
4. Apple `NSWindow.representedURL` 文档规定：空文件路径不显示 document icon；存在的文件路径显示相应文件类型 icon。[Apple NSWindow.representedURL](https://developer.apple.com/documentation/appkit/nswindow/representedurl)

### 3.2 推断

- 代码中的 `windowHandle()->setFilePath(图片绝对路径)` 是文档图标的直接触发点；清空原生 `filePath` 是移除 document proxy 的最小状态修复。
- 保留 bundle 的 `.icns`，同时只清空窗口级 icon，可以让 Finder/Dock 身份继续存在而不把应用身份绘制到窗口标题栏。

### 3.3 不确定性

- 本次系统 runner 在真实 Cocoa 窗口上断言 Qt 原生 `QWindow::filePath()`，没有使用 Accessibility 截图/OCR；“视觉上不显示”是基于 Qt/Apple 文档映射得到的可审计推断。
- macOS/Qt 版本差异可能影响标题栏布局，但空 `representedURL` 的无 document proxy 语义以 Apple 文档为准。
- 资源门禁基于小型 WebP/AVIF 目标负载，不能外推到任意超大图片或多窗口长期压力。

## 5. 测试用例规格

### TC-TITLEBAR-APP-ICON / AC-01

- **测试目的**：确认新建主窗口没有窗口级 App icon，同时确认资源中的应用 icon 没有被删除。
- **前置条件**：`QVApplication` 已构造；测试运行在 macOS；资源系统已初始化。
- **输入数据**：不加载文档的 `MainWindow`。
- **操作步骤**：构造 `MainWindow`；读取 `windowIcon()`；读取 `:/icons/Fovelle.png` 是否存在；关闭窗口。
- **预期结果**：`windowIcon().isNull()` 为真；应用资源存在；窗口关闭成功。
- **后置条件**：不修改 QSettings 和应用级 icon 状态。
- **测试代码**：`FeatureTests::testWindowIconIsCleared()`。

### TC-TITLEBAR-DOCUMENT-ICON / AC-02、AC-03

- **测试目的**：确认加载图片不会建立原生文档路径，并验证图片加载和标题显示没有回归。
- **前置条件**：Cocoa 平台可用；可创建临时目录；主窗口可见；测试关闭 last-window quit 以避免窗口关闭影响测试进程。
- **输入数据**：测试代码生成的有效 32×32 PNG。
- **操作步骤**：显示主窗口；调用 `openFile()`；等待 `getIsPixmapLoaded()`；读取 QWidget `windowFilePath()`、QWindow `filePath()`、窗口 icon 和标题。
- **预期结果**：图片加载成功；两个 file path 均为空；窗口 icon 为空；标题包含 PNG 文件名。
- **后置条件**：关闭窗口、释放临时目录、恢复原 quit policy。
- **测试代码**：`FeatureTests::testTitlebarDocumentProxyIsClearedForLoadedFile()`。

### TC-TITLEBAR-IDEMPOTENCE / AC-04

- **测试目的**：确认重复调用清空路径和 icon 的路径不会因文件切换或标题栏重建而恢复图标。
- **前置条件**：Cocoa 平台可用；可生成两个有效 PNG；主窗口可见。
- **输入数据**：第一张 PNG、第二张 PNG，以及 `setTitlebarHidden(true/false)` 两次状态切换。
- **操作步骤**：加载第一张图片并断言；隐藏标题栏并断言；显示标题栏并断言；加载第二张图片并再次断言。
- **预期结果**：每次观察到 `windowIcon()` 为空、QWidget file path 为空、QWindow file path 为空。
- **后置条件**：关闭窗口、释放临时目录、恢复原 quit policy。
- **测试代码**：`FeatureTests::testTitlebarIconClearingIsIdempotent()`。

### TC-BUNDLE-IDENTITY / AC-05

- **测试目的**：确认窗口级 icon 清空没有误删 bundle/Finder/Dock icon 或文件关联。
- **前置条件**：CMake bundle 已构建；`Info.plist` 可解析。
- **输入数据**：`build-fovelle-task/Fovelle.app`。
- **操作步骤**：读取 bundle executable、`Contents/Resources/qView.icns`、`CFBundleIdentifier`、`CFBundleIconFile` 和 WebP/AVIF extensions。
- **预期结果**：全部存在且字段值正确；bundle 仍可启动。
- **后置条件**：只读取构建产物，不修改 bundle。
- **测试代码**：`tests/quality_integration.py` 的 I-05。

### TC-SYSTEM-TITLEBAR / AC-02、AC-04、AC-08

- **测试目的**：在独立进程和真实 Cocoa QPA 下重复执行标题栏相关用例。
- **前置条件**：测试二进制已构建；可创建 Cocoa 可见窗口；`QT_FATAL_WARNINGS=1`。
- **输入数据**：`fovelle_tests` 进程及其固定 PNG fixture。
- **操作步骤**：运行 `quality_titlebar_system.py`；设置 `QT_QPA_PLATFORM=cocoa`；解析三个标题栏 case 和退出码；写入 JSON。
- **预期结果**：三个 case 全部 PASS；进程返回码为 0；原生 `QWindow::filePath` 断言和重复状态断言均出现。
- **后置条件**：测试进程结束；JSON 证据保留在 `reports/evidence/system-titlebar.json`。
- **测试代码**：[`tests/quality_titlebar_system.py`](../tests/quality_titlebar_system.py)。

### TC-SYSTEM-RESOURCE / AC-06、AC-07

- **测试目的**：验证真实 app 启动、加载目标格式和系统资源指标。
- **前置条件**：`Fovelle.app/Contents/MacOS/Fovelle` 可执行；系统提供 `ps`、`lsof`、`iostat`、`netstat`。
- **输入数据**：普通 WebP、普通 AVIF、带方向 WebP、带方向 AVIF，各 3 次，共 12 次；每次 hold 0.8s。
- **操作步骤**：运行 `quality_system_probe.py`；周期性采样进程 CPU/RSS/句柄/socket；采集主机磁盘和网络观察值；发送 SIGTERM 清理；聚合指标。
- **预期结果**：所有运行完成且无 Unsupported/Error 3；时间、吞吐、资源指标全部低于/高于对应门槛。
- **后置条件**：终止 runner 创建的进程；临时 fixture 自动删除；保留 `reports/evidence/system.json`。
- **测试代码**：[`tests/quality_system_probe.py`](../tests/quality_system_probe.py)。

## 6. 执行顺序与门禁

必须按以下顺序执行；任一阶段失败则总体不通过：

```bash
cmake --build build-fovelle-task --parallel
python3 tests/quality_static.py --build-dir build-fovelle-task --output reports/evidence/static.json
python3 tests/quality_unit_runner.py --binary build-fovelle-task/tests/fovelle_tests --output reports/evidence/unit.json
python3 tests/quality_integration.py --build-dir build-fovelle-task --output reports/evidence/integration.json
python3 tests/quality_titlebar_system.py --binary build-fovelle-task/tests/fovelle_tests --output reports/evidence/system-titlebar.json
python3 tests/quality_system_probe.py --app build-fovelle-task/Fovelle.app/Contents/MacOS/Fovelle --runs 3 --hold-seconds 0.8 --output reports/evidence/system.json
```
