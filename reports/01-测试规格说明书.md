## 4. 测试环境、固定输入和门槛

### 4.1 固定输入

- 单元测试图片由 `tests/tst_qviewtests.cpp` 在 `QTemporaryDir` 中确定性生成，颜色和尺寸固定，测试结束自动删除。
- 系统测试图片为仓库中的 `dist/mac/qView.icns`，避免依赖用户下载目录；应用输入为该文件的绝对路径。
- 构建命令：

  ```text
  cmake -S . -B build-quality-final -G Ninja -DBUILD_TESTS=ON \
    -DFOVELLE_BUILD_TRANSLATIONS=OFF \
    -DQV_DISABLE_ONLINE_VERSION_CHECK=ON -DCMAKE_BUILD_TYPE=Debug
  cmake --build build-quality-final --parallel 2
  ```

- 单元测试命令：`python3 tests/quality_unit_runner.py --binary build-quality-final/tests/fovelle_tests --output reports/evidence/unit.json`。
- 集成测试命令：`python3 tests/quality_integration.py --repo . --build-dir build-quality-final --output reports/evidence/integration.json`。
- 系统测试命令：`python3 tests/quality_system_probe.py --app build-quality-final/Fovelle.app/Contents/MacOS/Fovelle --image dist/mac/qView.icns --runs 5 --hold-seconds 0.8 --output reports/evidence/system.json`。

### 4.2 本地工程代理门槛（推断）

题目只规定了需要测量的指标，没有给数值范围。本次为可重复验收暂定：启动均值 ≤ 2 s、P99 ≤ 3 s、最大值 ≤ 5 s、吞吐 ≥ 0.5 次/s；进程 CPU 按逻辑 CPU 数归一化 ≤ 100%、RSS ≤ 512 MiB、磁盘空间占用 ≤ 95%、`iostat` 观测峰值 ≤ 500 MB/s、句柄 ≤ 512、进程网络 socket ≤ 4。这些阈值是测试设计推断，不应替代产品性能规格。

系统探针的启动时间是“进程出现”的可测代理，图片解码正确性由 QtTest 的异步加载测试覆盖；`iostat` 与 `netstat` 是主机级计数，可能包含背景活动，不能声称是精确的进程级磁盘/网络计费。

## 5. 原子测试用例

每个用例都明确给出测试目的、前置条件、输入数据、操作步骤、预期结果和后置条件。

### U-01 — Launch Services 文件事件入队和空事件幂等

- 验收标准：AC-12。
- 测试目的：验证 URL/文件事件立即返回、下一轮事件循环处理、空路径不改变状态。
- 前置条件：`QVApplication` 已创建；`QT_QPA_PLATFORM=cocoa`；无待处理文件事件。
- 输入数据：`QTemporaryDir` 中生成的 `32×32` PNG；`QFileOpenEvent(QUrl::fromLocalFile(path))`；`QFileOpenEvent(QString{})`。
- 操作步骤：

  1. 创建窗口并处理一次 Qt 事件。
  2. 直接发送本地 URL 文件事件，立即断言事件已接受且 `hasPendingFileOpenEvents()` 为真。
  3. 用 `QTRY_VERIFY_WITH_TIMEOUT` 等待队列为空和目标窗口 `isPixmapLoaded` 为真。
  4. 发送空路径事件，断言仍返回真且队列保持为空。

- 预期结果：事件回调不在调用栈内同步解码；路径最终与输入绝对路径一致；空事件不创建窗口、不崩溃、不重复加载。
- 后置条件：关闭测试窗口，恢复 `firstlaunch` QSettings 键。

### U-02 — 预加载器优先级、缓存、错误和析构

- 验收标准：AC-08。
- 测试目的：验证上游 `QVImageLoader` 的请求优先级、缓存复用、错误重试和析构期间不继续投递。
- 前置条件：QtTest 可用；临时目录可写；全局线程池可等待。
- 输入数据：5 张不同颜色 PNG；一个无效 PNG；desired image 列表含 priority `0/1/2`。
- 操作步骤：

  1. 监听 `loadStarted` 和 `imageReady`。
  2. 提交前台图和相邻/扩展预加载图，核对开始顺序和优先级。
  3. 重复提交已缓存图、移除 desired 集合、再提交并核对重新加载次数。
  4. 提交无效图，核对错误结果可再次重试。
  5. 在后台请求仍在排队时析构 loader，等待全局线程池结束。

- 预期结果：前台 priority `0` 先于预加载；缓存命中不重复 I/O；禁用保留后再次请求会重新加载；错误可重复报告；析构后无悬挂信号或崩溃。
- 后置条件：临时文件和 loader 自动销毁，线程池无残留任务。

### U-03 — Action clone 生命周期

- 验收标准：AC-07、AC-13。
- 测试目的：验证窗口克隆 action 的创建/取消跟踪不会改变全局 action 实例计数，并为 Open With 原生菜单占位策略提供生命周期基线。
- 前置条件：`QVApplication` 已初始化，action manager 可访问。
- 输入数据：一个临时 `MainWindow`，动作名 `fullscreen` 和 `open`。
- 操作步骤：

  1. 记录两个 action 的全局实例数。
  2. 显示临时窗口，确认克隆数增加。
  3. 关闭窗口，确认原始实例数恢复。

- 预期结果：临时窗口 action 被完全取消跟踪；不出现重复 action 或跨测试污染。
- 后置条件：窗口关闭，action manager 保持初始计数。

### U-04 — ColorSpace 和 QVMovie 基本行为

- 验收标准：AC-04、AC-10。
- 测试目的：验证图像转换函数真的将 sRGB 图像转到 Display P3，并验证自定义 QVMovie 的单帧读取和速度属性。
- 前置条件：QtGui 图像格式可用；测试进程已创建 `QVApplication`。
- 输入数据：8×8 sRGB 红色 `QImage`；临时单帧 PNG；目标色彩空间 `QColorSpace::DisplayP3`；速度 `50`。
- 操作步骤：

  1. 通过测试子类公开 `QVImageCore::handleColorSpaceConversion`。
  2. 转换图像并断言 `image.colorSpace()` 为 Display P3。
  3. 用 PNG 创建 QVMovie，断言 valid、frameCount 为 1。
  4. 设置速度 50%，断言 getter 返回 50。

- 预期结果：色彩空间转换完成；QVMovie 可读单帧且速度设置可观察。
- 后置条件：临时目录和 QVMovie 自动销毁。
