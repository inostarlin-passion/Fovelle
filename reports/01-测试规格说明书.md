本规格书只覆盖本次 GitHub Actions 失败修复：WebP/AVIF 带方向元数据的加载，以及 clang-tidy 检查配置。既有窗口功能的回归质量门禁仍作为系统级保护网执行。

## 2. 失败证据与根因假设

### 2.1 可验证事实

1. [Build Fovelle run 32107116589](https://github.com/inostarlin-passion/Fovelle/actions/runs/32107116589) 的测试日志显示 `testImageLoaderAppliesWebpOrientation` 实际为 `QSize(2x3)`，期望为 `QSize(3x2)`；同一测试此前直接调用原生 ImageIO 的断言已通过，失败点在 loader 结果断言。
2. [Checks run 32107116541](https://github.com/inostarlin-passion/Fovelle/actions/runs/32107116541) 的 clang-tidy 作业输出 `Error: no checks enabled.`。
3. 修复前 [`QVImageLoader::readFile`](../src/qvimageloader.cpp) 先调用 `QImageReader::read()`，只有在 Qt 返回空图时才调用原生 ImageIO；因此 Qt 返回非空但未应用方向变换时，原生路径不会执行。
4. 修复前 workflow 通过 `CMAKE_CXX_CLANG_TIDY=clang-tidy` 启用工具，但仓库没有 `.clang-tidy` 的显式检查集合。

### 2.2 推断

最小根因链为：Qt 6.8.3 的 WebP 插件在 CI 中返回了非空的未旋转图像 → 旧代码把“非空”误当作“方向已正确处理” → ImageIO 的方向感知回退被绕过 → loader 尺寸从期望的 `3x2` 变成 `2x3`。clang-tidy 则因为工具已启动但没有有效启用项而在每个编译命令上失败。

这是基于日志和源码顺序的推断；CI 日志没有直接打印 Qt 内部的变换状态，因此不把“Qt 插件一定不支持该元数据”表述为已观测事实。

### 2.3 外部可验证依据与不确定性

- Qt 官方文档说明 [`QImageReader::setAutoTransform`](https://doc.qt.io/qt-6/qimagereader.html) 控制基于图像元数据的自动变换。
- Apple 官方文档说明 [`kCGImageSourceCreateThumbnailWithTransform`](https://developer.apple.com/documentation/imageio/kcgimagesourcecreatethumbnailwithtransform?changes=__5) 可让 ImageIO 生成符合图像方向和宽高比的缩略图。
- LLVM 官方文档说明 [`clang-tidy`](https://clang.llvm.org/extra/clang-tidy/index.html) 通过 `-checks` 或 `.clang-tidy` 选择检查项。
- 本地验证使用 Qt 6.11.1/macOS 15.7.7，不是失败运行使用的 Qt 6.8.x/macOS 14；因此修复后的 GitHub runner 结果仍需在提交/推送后由远端重新执行确认。

## 3. 修复设计

1. 对 `QVCocoaFunctions::supportsAdditionalImageFormat()` 识别的 WebP/AVIF，先调用 `QVCocoaFunctions::readAdditionalImage()`；该实现使用 ImageIO 的方向变换选项。
2. 原生 ImageIO 返回空图时，保留 Qt `QImageReader` 路径作为回退；SVG、动画/多帧和其他格式的原有 Qt 行为不变。
3. 新增 [`.clang-tidy`](../.clang-tidy)，显式启用 `bugprone-use-after-move`、`performance-move-const-arg` 和 `clang-diagnostic-*`，并保留 `build.sh --tidy` 与 workflow 的 LLVM 安装契约。
4. 将根因契约加入静态检查 ST-06/ST-18 和集成检查 I-03/I-15，避免“代码修了但 CI 配置再次退化”。
