## 2. 根因分析的可验证依据

### 2.1 事实

1. Qt 的 `QImageReader::UnsupportedFormatError` 枚举值为 `3`；Qt 文档说明可读格式由内置处理器和运行时 image-format plugins 决定。[Qt QImageReader](https://doc.qt.io/qt-6/qimagereader.html)
2. Qt Image Formats 文档列出 WebP plugin 支持，但没有把 AVIF 列为 Qt 官方 image-format plugin；Qt plugin 必须在运行时可发现/部署。[Qt Image Formats](https://doc.qt.io/qt-6/qtimageformats-index.html)、[Qt Plugins](https://doc.qt.io/qt-6/deployment-plugins.html)
3. 原版 qView 的滚轮实现区分普通 wheel click 与 fractional/touch 输入：普通输入每个事件使用一个缩放步长，fractional 输入才按 `delta / 120` 计算幂指数。[qView upstream `qvgraphicsview.cpp`](https://raw.githubusercontent.com/jurplel/qView/master/src/qvgraphicsview.cpp)
4. Apple Image I/O 提供 `CGImageSourceCopyTypeIdentifiers()` 查询系统支持的源类型，并通过 `CGImageSourceCreateWithURL()` / `CGImageSourceCreateImageAtIndex()` 解码。[Apple Image I/O Guide](https://developer.apple.com/library/archive/documentation/GraphicsImaging/Conceptual/ImageIOGuide/imageio_basics/ikpg_basics.html)、[CGImageSourceCreateWithURL](https://developer.apple.com/documentation/imageio/cgimagesourcecreatewithurl%28_%3A_%3A%29?language=objc)
5. 本机 macOS 15.7.7 的 Image I/O 类型查询包含 `org.webmproject.webp` 和 `public.avif`；`sips` 可读取本规格生成的最小 WebP/AVIF fixture。

### 2.2 推断

1. “Unsupported image format (Error 3)” 的直接原因是：当前 Qt 运行时 imageformats 目录没有可用的 WebP/AVIF Qt plugin，且 AVIF 本身不在 Qt 官方 Image Formats 列表中；文件内容不是根因。推断由 Qt 错误枚举、当前插件目录、Image I/O 成功解码三组证据交叉支持。
2. 缩放幅度过大的原因是原实现对所有 wheel event 都使用 `delta / 120` 作为幂指数；当一个普通鼠标事件携带 `delta=240` 时，会变成 `1.25²`，而 qView 普通 mouse wheel 应只应用一个离散步长。
3. 标题栏图标来自应用级 icon 继承：原实现通过 `QApplication::setWindowIcon(...)` 设置全局 icon。修复后保留 bundle icon 供 Finder/Dock 使用，在 `MainWindow` 级别清空 window icon。

### 2.3 不确定性与边界

- 如果用户自行部署了 Qt WebP plugin，Qt 可能先行成功解码；fallback 仍保持条件触发，不会重复替换成功结果。
- AVIF 支持取决于运行时 macOS Image I/O 返回的 UTI 集合；代码不硬编码宣称所有旧 macOS 版本都支持 AVIF。
- CPU、RSS、句柄、网络 socket 是进程采样；磁盘 I/O 和网络字节是主机级观测，可能包含系统后台活动。报告不会把这些主机观测误称为应用专属计量。

## 3. 原子验收标准

| 编号 | 原子标准 | 可观察判定 | 对应用不变量的约束 |
|---|---|---|---|
| AC-01 | 移除窗口标题栏中的 App 图标 | QApplication 不再设置全局 window icon；新建图片窗口 `windowIcon().isNull()`；bundle icon 文件仍存在 | Finder/Dock 图标不被删除 |
| AC-02 | 普通鼠标滚轮缩放使用一个离散步长 | `delta=240` 且倍率 `1.25` 时结果为 `1.25`；反向为 `0.8`，不是 `1.5625` | 正负方向互为倒数 |

## 4. 逐条测试用例

### TC-01 / AC-01：窗口标题栏不显示 App 图标

- **测试目的**：验证图片窗口清空 icon，同时保留 bundle/Finder/Dock 资源。
- **前置条件**：已构建 `fovelle_tests`；Qt Cocoa 平台可用；`:/icons/Fovelle.png` 已编入资源。
- **输入数据**：无外部图片；`QVApplication` 实例和一个 `MainWindow`。
- **操作步骤**：运行 `FeatureTests::testWindowIconIsCleared()`；读取应用 icon、窗口 icon、Qt resource 是否存在。
- **预期结果**：应用 icon 和窗口 icon 均为 null；资源 `:/icons/Fovelle.png` 存在；测试进程退出码为 0。
- **后置条件**：关闭测试窗口，不修改用户设置。

### TC-02 / AC-02：普通鼠标滚轮单步缩放

- **测试目的**：验证普通 mouse wheel 不因一个事件携带多个 120-unit 而过度放大。
- **前置条件**：已编译 `QVGraphicsView::wheelZoomFactor()`；倍率设为 `1.25`。
- **输入数据**：`wheelDelta=240`、`-240`，`useFractionalSteps=false`。
- **操作步骤**：调用纯函数两次并比较结果；检查正向和反向乘积。
- **预期结果**：正向结果为 `1.25`，反向结果为 `0.8`，二者乘积为 `1.0`。
- **后置条件**：无 UI 状态变更；纯函数测试结束。

### TC-03 / AC-03：触控板 fractional 缩放

- **测试目的**：验证平滑输入仍可按真实 wheel delta 进行 fractional 缩放。
- **前置条件**：已编译同一纯函数；倍率设为 `1.25`。
- **输入数据**：`wheelDelta=240`、`useFractionalSteps=true`。
- **操作步骤**：调用 `wheelZoomFactor()`，将结果与 `pow(1.25, 2)` 比较。
- **预期结果**：结果为 `1.5625`；与 TC-02 的离散结果有明确区分。
- **后置条件**：无 UI 状态变更。

### TC-04 / AC-04：WebP Image I/O fallback 解码

- **测试目的**：验证 Qt 读取失败后，macOS Image I/O 能解码 WebP。
- **前置条件**：macOS Image I/O 返回 `org.webmproject.webp`；Qt 测试进程链接 CoreGraphics/ImageIO。
- **输入数据**：测试代码内嵌的最小有效 WebP，写入临时 `native-webp.webp`。
- **操作步骤**：断言 native format 支持；通过 `QVImageLoader::requestImage()` 异步读取；等待 `imageReady` 最长 5 s。
- **预期结果**：结果存在，QImage 非空且尺寸为 `1×1`，`errorData` 不存在。
- **后置条件**：临时目录和 loader 释放；不残留测试文件。

### TC-05 / AC-05：AVIF Image I/O fallback 解码

- **测试目的**：验证 Qt 无 AVIF plugin 时，macOS Image I/O 能解码 AVIF。
- **前置条件**：macOS Image I/O 返回 `public.avif`；测试 target 链接 ImageIO/CoreGraphics。
- **输入数据**：测试代码内嵌的最小有效 AVIF，写入临时 `native-avif.avif`。
- **操作步骤**：断言 native format 支持；通过 `QVImageLoader` 异步读取；等待 `imageReady` 最长 5 s。
- **预期结果**：结果存在，QImage 非空且尺寸为 `1×1`，不产生 `UnsupportedFormatError (3)`。
- **后置条件**：临时目录和 loader 释放。

### TC-06 / AC-06：Settings → Formats 与统一扩展注册表同步

- **测试目的**：验证新增格式既能参与应用文件识别，也能出现在 Formats 设置页面的数据源中。
- **前置条件**：`QVApplication::defineFilterLists()` 已执行；`QVOptionsDialog::syncFormats()` 可被静态集成检查定位。
- **输入数据**：native formats 列表中的 `webp`、`avif`，以及 AVIF 别名 `.avifs`。
- **操作步骤**：运行 `FeatureTests::testSettingsFormatsIncludeNativeImageFormats()`；集成检查确认 `syncFormats()` 使用 `getAllFileExtensionList()`。
- **预期结果**：应用完整扩展集合包含 `.webp`、`.avif`、`.avifs`；Settings table 使用同一完整集合；测试通过。
- **后置条件**：不保存 transient settings，不改变用户禁用格式配置。

### TC-07 / AC-07：构建、链接与 bundle 集成

- **测试目的**：验证改动不是只在单元测试源文件中有效。
- **前置条件**：CMake 构建目录已配置；系统安装 qmake。
- **输入数据**：`CMakeLists.txt`、`qView.pro`、`tests/CMakeLists.txt`、`Fovelle.app/Contents/Info.plist`。
- **操作步骤**：执行 CTest；执行 qmake 配置；读取 bundle executable、`qView.icns`、identifier 和 document extensions。
- **预期结果**：CTest、qmake 均返回 0；CoreGraphics/ImageIO 链接声明存在；bundle 含 icon、可执行文件，并声明 webp/avif/avifs。
- **后置条件**：qmake 临时输出目录自动删除；构建产物保留供审计。

### TC-08 / AC-08：静态与编译门禁

- **测试目的**：检查语法、编译、diff 格式和本次测试 marker。
- **前置条件**：仓库工作树可读；`clang-format` 若不存在则启用 CMake build fallback。
- **输入数据**：所有 `tests/quality_*.py`、本次改动 C++/Objective-C++ 文件和工作树 diff。
- **操作步骤**：执行 `quality_static.py`，检查 ST-01～ST-09。
- **预期结果**：Python AST 无错误，CMake build 成功，`git diff --check HEAD` 返回 0，六个当前范围核心测试 marker 全部存在。
- **后置条件**：静态证据写入 `reports/evidence/static.json`。

### TC-09 / AC-09：系统时间行为

- **测试目的**：在目标启动负载下测量平均、P99、最大启动时间和吞吐率。
- **前置条件**：已构建 `Fovelle.app/Contents/MacOS/Fovelle`；macOS Cocoa 桌面可启动应用。
- **输入数据**：自动生成的 WebP/AVIF fixture；每种格式 3 次；单次保持窗口 0.8 s。
- **操作步骤**：执行 `quality_system_probe.py`；使用 `ps` 采样并在保持时间后发送 SIGTERM；聚合指标。
- **预期结果**：两种格式均完成 3 次启动；平均 ≤2 s，P99 ≤3 s，最大 ≤5 s，吞吐 ≥0.5 次/s；stderr 不含 Unsupported image format/Error 3。
- **后置条件**：临时 fixture 和应用进程清理；证据写入 `reports/evidence/system.json`。

### TC-10 / AC-10：系统资源行为

- **测试目的**：验证目标负载下 CPU、内存、磁盘、网络、句柄和 socket 处于显式阈值内。
- **前置条件**：与 TC-09 相同；`ps`、`lsof`、`iostat`、`netstat` 可用。
- **输入数据**：TC-09 的 6 次应用启动和相同 hold 时间。
- **操作步骤**：记录进程级 CPU/RSS/句柄/socket；记录主机级磁盘 I/O、磁盘空间和网络 counter 前后差值；与阈值比较。
- **预期结果**：CPU ≤100%（按逻辑 CPU 归一化），RSS ≤768 MiB，磁盘空间 ≤95%，磁盘 I/O ≤500 MB/s，网络增量 ≤64 MiB，句柄 ≤512，socket ≤4。
- **后置条件**：明确标记主机级观测的归属限制；证据保留在 system JSON。

## 5. 执行顺序与命令

```bash
cmake -S . -B build-fovelle-task -DBUILD_TESTS=ON \
  -DFOVELLE_BUILD_TRANSLATIONS=OFF \
  -DQV_DISABLE_ONLINE_VERSION_CHECK=ON
cmake --build build-fovelle-task --parallel 2

python3 tests/quality_static.py \
  --build-dir build-fovelle-task --output reports/evidence/static.json
python3 tests/quality_unit_runner.py \
  --binary build-fovelle-task/tests/fovelle_tests --output reports/evidence/unit.json
python3 tests/quality_integration.py \
  --build-dir build-fovelle-task --output reports/evidence/integration.json
python3 tests/quality_system_probe.py \
  --app build-fovelle-task/Fovelle.app/Contents/MacOS/Fovelle \
  --runs 3 --hold-seconds 0.8 --output reports/evidence/system.json
```

四阶段必须按静态→单元→集成→系统顺序执行；任一阶段失败即停止交付判定。
