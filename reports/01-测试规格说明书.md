# Fovelle 测试规格说明书

**文档编号**：TS-FOVELLE-2026-08-17
**版本**：1.0
**执行顺序**：单元测试 → 集成测试 → 系统测试
**适用平台**：macOS；本次验收不定义 Windows/Linux 兼容性
**被测版本**：Fovelle 0.1.0
**仓库**：[inostarlin-passion/Fovelle](https://github.com/inostarlin-passion/Fovelle)

## 1. 目的与范围

本规格书把用户需求拆成可独立判定的原子验收标准，并为每条标准定义可重复的测试用例。范围包括：品牌与应用身份、图标、窗口关闭与 Esc 行为、About 页、更新检查地址、macOS Bundle/CMake/qmake、CI、非 macOS 清理，以及代码质量要求中的时间、资源和可测试性。

不在本次自动化范围内的事项：Apple Developer 签名/公证、Finder/Dock 缓存刷新后的人工视觉确认、不同 macOS/Qt/CPU 组合的兼容性矩阵，以及真实 GitHub Release 发布后的升级下载流程。

## 2. 可验证依据与判定边界

### 2.1 事实

以下是本次测试所直接观测或由权威文档支持的事实：

- 当前远程仓库的默认分支为 `main`；集成脚本从 Git 远程符号引用和工作区文件读取，不以报告文字代替检查。
- Qt 文档说明 `lastWindowClosed()` 在最后一个可见主窗口关闭时发出，`quitOnLastWindowClosed` 控制应用是否随后退出：[QGuiApplication](https://doc.qt.io/qt-6/qguiapplication.html#lastWindowClosed-signal)。
- Qt 文档说明 `QShortcut::activated()` 在快捷键序列完成时发出：[QShortcut](https://doc.qt.io/qt-6/qshortcut.html)。
- CMake 的 macOS Bundle 属性用于设置 GUI identifier、Bundle name、版本和图标等信息：[MACOSX_BUNDLE_GUI_IDENTIFIER](https://cmake.org/cmake/help/latest/prop_tgt/MACOSX_BUNDLE_GUI_IDENTIFIER.html)、[MACOSX_BUNDLE_ICON_FILE](https://cmake.org/cmake/help/latest/prop_tgt/MACOSX_BUNDLE_ICON_FILE.html)。
- Apple 的 Bundle 资源文档将 `CFBundleIconFile` 定义为应用图标资源键：[CFBundleIconFile](https://developer.apple.com/documentation/bundleresources/information_property_list/cfbundleiconfile)。
- 更新检查地址应指向本项目仓库；GitHub Release API 的官方路径说明见：[List releases](https://docs.github.com/en/rest/releases/releases#list-releases)。
- GitHub 页面显示 [`jdpurcell/qView`](https://github.com/jdpurcell/qView) 是 [`jurplel/qView`](https://github.com/jurplel/qView) 的 fork，其仓库包含 GPLv3 许可证；这支持在 README/About 中标注来源，但不自动证明每个文件的作者归属。

### 2.2 推断

- 用户没有给出数值化性能/资源 SLO，因此本规格书选择了保守的本地工程门槛，用于发现明显回归，不等同于生产承诺。
- 运行时图标采用用户提供的 PNG 作为 Qt 资源，并从同一 PNG 生成 macOS `.icns`；这是在“不改文件名”的约束下同时覆盖窗口图标和 Bundle 图标的最小实现。
- 最后窗口退出行为由应用设置 `setQuitOnLastWindowClosed(true)` 与 Qt 的已记录框架语义共同构成；测试不会让测试进程在中途真的退出，而是验证策略、关闭事件和静态实现。

### 2.3 不确定性

- 系统探针的磁盘 I/O 和网络字节数是主机级计数器，可能包含后台进程活动；CPU、RSS、句柄和 socket 是被测进程采样值。
- 当前 Cocoa 自动化环境对“真实物理键盘在原生全屏窗口上发送 Esc”的事件投递不稳定，因此单元测试验证了 Escape 绑定并确定性触发同一个 `QShortcut::activated` 分支；物理键盘仍需人工验收。
- 更新检查在测试构建中使用 `QV_DISABLE_ONLINE_VERSION_CHECK=ON`，因此本次验证仓库地址和版本比较逻辑，没有对 GitHub 网络服务执行破坏性或依赖 Release 内容的操作。

## 4. 性能与资源验收门槛

以下数值是本次验收的工程推断门槛，不是用户未声明的产品 SLA：

| 指标 | 门槛 | 观测方式 |
|---|---:|---|
| 启动平均值 | ≤ 2.0 s | 5 次独立进程启动 |
| 启动 P99 | ≤ 3.0 s | 5 次样本的保守离散 P99 |
| 启动最大值 | ≤ 5.0 s | 5 次独立启动 |
| 吞吐率 | ≥ 0.5 次启动/s | 启动总耗时倒数 |
| CPU | ≤ 100%（按逻辑 CPU 数归一化） | `ps` 进程采样 |
| RSS | ≤ 524288 KiB | `ps` 进程采样 |
| 磁盘空间使用率 | ≤ 95% | `shutil.disk_usage` |
| 磁盘 I/O | ≤ 500 MB/s | `iostat` 主机观测 |
| 网络 I/O | ≤ 64 MiB/本轮主机字节增量 | `netstat -ib` 主机观测 |
| 打开句柄 | ≤ 512 | `lsof -p` |
| 网络 socket | ≤ 4 | `lsof -a -i` |

### 单元测试用例

#### U-01 图标资源与运行时图标

- **测试目的**：验证应用运行时使用 Fovelle 图标资源。
- **前置条件**：已构建 `fovelle_tests`；Qt resource system 已加载。
- **输入数据**：指定 PNG、`:/icons/Fovelle.png`、64×64 图标请求。
- **操作步骤**：创建 `QVApplication`；读取 `windowIcon()`；读取 Qt 资源；请求 64×64 pixmap。
- **预期结果**：图标非空、pixmap 非空、资源存在；集成阶段再验证源文件字节一致和 ICNS magic。
- **后置条件**：测试应用退出；不修改源 PNG。

#### U-02 应用/组织身份

- **测试目的**：验证 Fovelle 的 organization、domain、application、display name 和版本。
- **前置条件**：测试入口按生产入口设置 identity。
- **输入数据**：`Fovelle`、`io.github.inostarlin-passion`、`0.1.0`。
- **操作步骤**：读取 `QCoreApplication`/`QGuiApplication` 静态身份属性并逐项比较。
- **预期结果**：五项均精确匹配，无 qView 运行时身份。
- **后置条件**：身份仅存在于测试进程内，不写设置。

#### U-03 窗口标题

- **测试目的**：验证空窗口标题以 Fovelle 为品牌基线。
- **前置条件**：`MainWindow` 可创建；关闭退出策略暂时关闭以避免结束测试事件循环。
- **输入数据**：无文件的 `MainWindow`。
- **操作步骤**：创建窗口，调用 `buildWindowTitle()`，读取 `windowTitle()`。
- **预期结果**：标题为 `Fovelle`。
- **后置条件**：关闭窗口并恢复退出策略。

#### U-04 About 页

- **测试目的**：验证 About 页的可见文本、Fovelle 仓库链接和 qView 来源署名。
- **前置条件**：`QVAboutDialog` 可创建；版本设置为 `0.1.0`。
- **输入数据**：用户给定 About 文本块、`https://github.com/inostarlin-passion/Fovelle` 和 `https://github.com/jdpurcell/qView`。
- **操作步骤**：创建对话框；读取标题、logo、subtitle 和 info label；将 HTML 转为可见纯文本；检查两个 URL、署名和旧官网。
- **预期结果**：可见文本精确为：

  ```text
  Based on qView
  Copyright © 2018–2025 jurplel and qView contributors
  Fovelle modifications © 2026 Fovelle contributors
  Includes portions of commits from jdpurcell/qView by jdpurcell

  Licensed under GPLv3
  ```

  标题为 `About Fovelle`，版本为 `version 0.1.0`，两个 URL 和署名均存在且不含旧官网。
- **后置条件**：对话框销毁；不发送更新请求。

#### U-05 最后窗口关闭策略

- **测试目的**：验证应用采用最后窗口关闭退出策略。
- **前置条件**：`QVApplication` 已创建。
- **输入数据**：`quitOnLastWindowClosed=true` 和一个可见 `MainWindow`。
- **操作步骤**：读取策略为 `true`；为避免测试进程被 Qt 退出，临时设为 `false`；显示并关闭唯一测试窗口；确认窗口不可见；恢复策略。
- **预期结果**：生产初始化策略为 `true`，关闭操作完成且窗口不可见；Qt 的最后窗口退出语义由集成/框架依据覆盖。
- **后置条件**：恢复原策略，销毁测试窗口。

#### U-06 全屏 Esc

- **测试目的**：验证全屏状态下 Escape shortcut 退出全屏。
- **前置条件**：`MainWindow` 可进入全屏；退出策略临时关闭；当前 Cocoa 环境可创建全屏窗口。
- **输入数据**：`Qt::Key_Escape`，以及其对应的 `QShortcut::activated` 事件。
- **操作步骤**：显示窗口并进入全屏；读取 shortcut key；确定性触发同一个 `activated` 分支；等待窗口恢复普通状态。
- **预期结果**：shortcut key 为 Escape；窗口不再全屏且仍可见。
- **后置条件**：关闭窗口，恢复退出策略。

#### U-07 非全屏 Esc

- **测试目的**：验证普通窗口状态下 Escape shortcut 关闭窗口。
- **前置条件**：普通可见 `MainWindow`；退出策略临时关闭。
- **输入数据**：`Qt::Key_Escape`，以及其对应的 `QShortcut::activated` 事件。
- **操作步骤**：显示并激活窗口；核对 shortcut key；触发同一 shortcut；等待窗口不可见。
- **预期结果**：窗口被关闭，不发生全屏切换。
- **后置条件**：恢复退出策略并释放窗口。
