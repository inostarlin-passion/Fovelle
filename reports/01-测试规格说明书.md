## 2. 事实、推断与不确定性

### 2.1 可验证事实

1. 本地代码原先在 `MainWindow` 中创建独立的 Return 和数字键盘 Enter `QShortcut`；本次实现删除这两个绕过设置的快捷键，并把 Full Screen QAction 的默认值设为 `Qt::Key_Return`。
2. Qt 的 [`QShortcut` 文档](https://doc.qt.io/qt-6/qshortcut.html)规定快捷键由 `QShortcut::key`/`QAction` 等对象持有；[`QKeySequence` 文档](https://doc.qt.io/qt-6/qkeysequence.html)说明标准 FullScreen 序列依平台而异，因此不能把平台标准序列当作本需求的固定 Enter 默认值。
3. 本地旧实现的默认画面背景是 `#212121`；旧的 “Titlebar always dark” 通过 AppKit vibrancy 设置深色外观。本次兼容迁移逻辑读取旧键，但新设置库只暴露 `theme`。
4. Apple 的 [选择特定 AppKit 外观](https://developer.apple.com/documentation/AppKit/choosing-a-specific-appearance-for-your-macos-app)示例支持显式指定 Aqua/Dark Aqua；Apple 的 [Aqua](https://developer.apple.com/documentation/appkit/nsappearance/name-swift.struct/aqua?language=objc) 和 [Dark Aqua](https://developer.apple.com/documentation/appkit/nsappearance/name-swift.struct/darkaqua?language=objc) 页面分别定义标准浅色/深色外观。
5. Apple 的 [Preview 窗口背景说明](https://support.apple.com/en-ie/guide/preview/prvw1003/mac)确认 Preview 在图像/PDF 周围显示灰色窗口背景，并允许用户修改该背景色；它没有给出本文所需的固定 RGB 采样值。
6. Qt 的 [`QWidget`](https://doc.qt.io/qt-6.5/qwidget.html) 和 [`QPalette`](https://doc.qt.io/qt-6.8/qpalette.html) 文档说明控件背景和调色板角色会影响绘制，但 macOS 原生标题栏仍由 AppKit 外观控制。
7. 上游 [qView 仓库](https://github.com/jdpurcell/qView)可用于确认 Practical/Verbose 是既有标题栏模式；本规格书以本地需求的字段顺序为准。

### 2.2 本实现采用的推断

- 将 Light Theme 映射为标准 AppKit `Aqua`、画面背景 `#969696`；将 Dark Theme 映射为标准 AppKit `DarkAqua`、画面背景 `#212121`。`#969696` 来自用户提供的 Preview 截图采样；这是针对该参考截图的可复现实现，而不是声称所有 macOS/Preview 配置都使用同一 RGB 值。
- “Enter 键”在默认快捷键验收中采用 Qt `Qt::Key_Return`（主键盘 Return/Enter）；数字键盘 `Qt::Key_Enter` 只有在用户显式配置相应快捷键时才应生效。

### 2.3 未消除的不确定性

- Apple 文档未提供 Preview 当前 macOS 版本的标题栏/主体区域固定 RGB 值，且 Preview 背景可在设置中修改。因此系统用例验证 `Aqua`/`DarkAqua` 原生外观名和本应用画面区域的确定性颜色，不冒充对 Preview 截图的 OCR 或逐像素比对。
- 全屏时间指标来自 Cocoa 测试进程合成的 Qt 键事件；它验证事件到 Qt 全屏状态确认的响应窗口，不等价于任意硬件键盘、显示器或人工操作的端到端延迟。

### 2.4 根因链与修复策略

1. 截图事实：用户提供的 Preview 截图尺寸为 3448×1960；图像外侧的均匀留白区域采样为 RGB `(150,150,150)`，即 `#969696`。
2. 代码事实：Light Theme 在 `MainWindow::settingsUpdated()` 中把 `customBackgroundColor` 设为 `QColorConstants::White`；`paintEvent()` 随后直接用该值填充画面区域。
3. 平台事实：代码调用 Aqua 只改变 AppKit 原生窗口外观；Qt 自绘的画面区域仍由 `customBackgroundColor` 决定，不能因为标题栏是 Aqua 就自动获得 Preview 的灰色。
4. 根因结论：问题是 Light Theme 的应用自绘背景常量错误，而不是图片解码、缩放、棋盘格或原生标题栏外观问题。
5. 修复策略：保留 Aqua 标题栏和棋盘格优先级，仅把 Light Theme 自绘背景改为 `QColor("#969696")`，并将该 RGB 固化为回归测试输入。

## 4. 测试环境、数据与不变量

### 4.1 环境

- 构建：`cmake --build build-fovelle-task --parallel 4`。
- Qt 测试：`QT_QPA_PLATFORM=cocoa`，并在质量脚本中启用 `QT_FATAL_WARNINGS=1`。
- 设置隔离：`ScopedOptionValues` 和 `ScopedShortcutValues` 保存、修改、恢复 `QSettings`；每个测试的后置条件恢复应用退出策略和设置值。
- 系统测试必须串行运行。macOS Cocoa 窗口焦点、全屏状态和原生窗口资源是共享桌面状态，不能把多个 GUI 测试进程并行作为正式证据。

### 4.2 输入数据

| 数据 | 用途 |
|---|---|
| `Qt::Key_Return`、`Qt::Key_Enter`、`Qt::Key_Space`、`Qt::Key_Escape` | 快捷键边界与配置行为 |
| `01-practical.png`、`01-verbose.png`、`02-other.png`，64×48 | 标题栏文件名、序号、分辨率和文件大小 |
| 125% 显式缩放 | Verbose 缩放比例字段 |
| 透明 1×1 PNG | 棋盘格覆盖与恢复 |
| `Light Theme`/`Dark Theme` | 设置控件和主题切换 |
| `Aqua`/`DarkAqua`、`#969696`、`#ffffff`、`#cccccc`、`#212121` | 原生外观、Preview 参考背景和棋盘格/深色背景观测值 |

### 4.3 不变量

- 用户清空 Full Screen 快捷键后，应用不得通过其他隐藏的 Return/Enter 快捷键改变全屏状态。
- Theme 变化不应改变 Checkerboard 选项的持久化值；Checkerboard 开启时覆盖画面填充，关闭后恢复所选 Theme。
- 标题字段顺序固定，文件大小使用现有 `QVInfoDialog::formatBytes`，缩放比例保留一位小数。
- 测试不得把临时设置和临时文件泄漏到用户配置或后续测试。

以下每个用例都包含测试目的、前置条件、输入数据、操作步骤、预期结果和后置条件；“固化代码”给出可追溯的实现入口。

### TC-FS-DEFAULT — AC-01

- 测试目的：验证 Full Screen 默认 Enter 快捷键同时出现在设置记录和 QAction。
- 前置条件：Qt 应用、ShortcutManager、ActionManager 已初始化。
- 输入数据：`fullscreen` 设置键、`Qt::Key_Return`。
- 操作步骤：保存 Return 到 `shortcuts/fullscreen`；调用 `updateShortcuts()`；读取 ShortcutManager 记录和 `fullscreen` QAction 的 `shortcuts()`。
- 预期结果：默认值和当前值都只有 Return；QAction 只有一个 Return 序列。
- 后置条件：`ScopedShortcutValues` 恢复原设置并刷新快捷键。
- 固化代码：`WindowBehaviorTests::testFullscreenDefaultShortcutIsEnterAndConfigurable`。

### TC-FS-NO-BYPASS — AC-02

- 测试目的：验证清空设置后没有隐藏的 Return/数字键盘 Enter 全屏入口。
- 前置条件：可见且非全屏的 `MainWindow`，`shortcuts/fullscreen` 显式为空。
- 输入数据：`Qt::Key_Return`、`Qt::Key_Enter`。
- 操作步骤：刷新 ShortcutManager；枚举窗口子对象中的 `QShortcut`；向窗口发送两个按键并处理事件。
- 预期结果：没有对应的独立 QShortcut，窗口保持非全屏。
- 后置条件：关闭窗口，恢复快捷键和应用退出策略。
- 固化代码：`WindowBehaviorTests::testEnterDoesNotBypassClearedFullscreenShortcut`。

### TC-FS-CONFIGURED — AC-03
