## 2. 多跳检索与根因分析

### 2.1 可验证事实

1. Qt `QImageReader::setAutoTransform(true)` 会在读图时应用图像变换元数据，且 `transformation()` 可表示方向变换。[Qt QImageReader](https://doc.qt.io/qt-6/qimagereader.html)
2. Apple Image I/O 将 `kCGImagePropertyOrientation` 定义为图像的显示方向属性；该属性按 TIFF/EXIF 方向编码。[Apple `kCGImagePropertyOrientation`](https://developer.apple.com/documentation/imageio/kcgimagepropertyorientation?changes=_4)
3. Apple 的 `kCGImageSourceCreateThumbnailWithTransform` 选项用于把缩略图旋转/缩放到符合图像方向和宽高比；默认值为 false。[Apple `kCGImageSourceCreateThumbnailWithTransform`](https://developer.apple.com/documentation/imageio/kcgimagesourcecreatethumbnailwithtransform?changes=__5)
4. Apple 文档要求通过 `CGImageSourceCreateThumbnailAtIndex` 生成缩略图时提供 `kCGImageSourceCreateThumbnailFromImageIfAbsent` 或 `...Always` 等选项。[Apple `CGImageSourceCreateThumbnailAtIndex`](https://developer.apple.com/documentation/imageio/cgimagesourcecreatethumbnailatindex%28_%3A_%3A_%3A%29)
5. 本仓库的 Qt 路径已经调用 `setAutoTransform(true)`；但原生 WebP/AVIF fallback 在修复前使用 `CGImageSourceCreateImageAtIndex(source, 0, nullptr)`，没有传递方向变换选项。这是代码事实，不是对运行结果的猜测。
6. 当前 `QVGraphicsView::resizeEvent()` 会调用 `fitOrConstrainImage()`；该函数只有在 `calculatedZoomMode` 有值时才调用 `recalculateZoom()`。手动 `zoomAbsolute()` 在修复前会清空该 mode。
7. 原版 qView 当前源码将普通 wheel click 与 touch device 的 fractional delta 分开处理；普通输入采用一个符号化步长，fractional 输入才使用 `delta / 120`。[qView upstream `qvgraphicsview.cpp`](https://raw.githubusercontent.com/jurplel/qView/master/src/qvgraphicsview.cpp)
8. qView 发布记录曾包含 fullscreen 窗口尺寸复位修复，说明 fullscreen 与窗口尺寸/视图状态的交互是已有产品风险面。[qView Releases](https://github.com/jurplel/qView/releases)
9. 本次最终系统探针在本机 macOS 15.7.7 / arm64 上对四类 fixture 各启动 3 次，共 12 次；全部没有 `Unsupported image format` 或 `Error 3` 文本。具体数字见 [`system.json`](evidence/system.json)。

### 2.2 基于事实的推断

- **方向根因推断**：Qt 成功路径会自动变换，但 fallback 绕过 Qt 且把 Image I/O 方向选项留空，因此带 EXIF/AVIF rotation item 的图片在 fallback 输出中只保留原始像素排列，导致显示方向与正确方向不同。修复应在 Image I/O 解码阶段应用元数据，而不是在 UI 层按后缀猜旋转角度。
- **全屏缩放根因推断**：打开图片时 `ZoomToFit` mode 保存了当前窗口的 fit 比例；滚轮上、下两步数值回到原比例，但 mode 已被清空。进入 fullscreen 后视口改变，`fitOrConstrainImage()` 只能约束位置，旧比例被保留，所以图片相对新窗口偏小。修复应恢复“稳定比例对应的 fit 意图”，再让新视口重新计算。
- **实现选择推断**：最近一次稳定的 sticky calculated mode 和比例足以识别“逆向滚轮回到 fit”；如果用户停在其他比例，则不恢复 mode，从而不破坏真正的手动缩放。

### 2.3 不确定性与边界

- Image I/O 是否支持 AVIF 由当前 macOS 的 UTI 集合决定；代码通过运行时查询，不宣称所有旧 macOS 都支持 `public.avif`。
- 不同编码器可能把方向写入 EXIF、HEIF/AVIF `irot` 或其他容器属性；本次 fixture 覆盖 WebP EXIF RightTop 和 AVIF `irot`，不等价于覆盖所有厂商元数据变体。
- 系统 CPU/RSS/句柄/socket 是进程采样；`iostat`/`netstat` 的磁盘和网络数据是主机观测，可能包含后台活动。它们用于目标负载门禁，不是单进程精确 I/O 账本。
- 本次系统 probe 验证启动、错误文本和资源指标；像素方向由 Qt 单元测试直接断言，避免把“窗口没有报错”误当作“方向正确”。

## 4. 原子测试用例

### TC-ORI-WEBP / AC-ORI-01

- **测试目的**：确认带 EXIF RightTop 的 WebP 在 native decoder 和 `QVImageLoader` 中都完成方向变换。
- **前置条件**：macOS Image I/O 返回 WebP UTI；测试 target 链接 CoreGraphics/ImageIO；临时目录可写。
- **输入数据**：测试代码内嵌的无损 2×3 WebP；原始角点为 red/green/blue/yellow/magenta/cyan，EXIF orientation 为 RightTop。
- **操作步骤**：写出 `oriented-webp.webp`；调用 `QVCocoaFunctions::readAdditionalImage()`；检查尺寸和四角；再通过 `QVImageLoader` 等待 `imageReady`，检查相同尺寸和错误状态。
- **预期结果**：两个路径均输出 3×2；四角依次为左上 magenta、右上 red、左下 cyan、右下 green；`errorData` 不存在。
- **后置条件**：loader、临时文件和临时目录释放。

### TC-ORI-AVIF / AC-ORI-02

- **测试目的**：确认带 AVIF `irot` rotation item 的图片不会以编码器原始方向显示。
- **前置条件**：macOS Image I/O 返回 AVIF UTI；测试 target 已链接 ImageIO/CoreGraphics；临时目录可写。
- **输入数据**：由同一 2×3 色块生成、带 `irot` 的无损 AVIF。
- **操作步骤**：写出 `oriented-avif.avif`；直接调用 native decoder 检查尺寸；再经 `QVImageLoader` 异步读取。
- **预期结果**：native 和 loader 均输出 3×2；结果非空、无 `errorData`，不产生 `UnsupportedFormatError`。
- **后置条件**：释放 loader 和临时 fixture。

### TC-ZOOM-FULLSCREEN / AC-ZOOM-01、AC-ZOOM-02

- **测试目的**：复现“非全屏 fit → 滚轮上一步/下一步 → fullscreen”路径，验证 mode 和比例相对新视口连续。
- **前置条件**：Cocoa 平台可创建可见 `MainWindow`；临时 1600×900 PNG 可读；窗口初始为非全屏。
- **输入数据**：`ZoomToFit`；一个 `zoomIn()` 和一个 `zoomOut()`；真实 `MainWindow::toggleFullScreen()` enter/exit。
- **操作步骤**：加载图片并将窗口设为 640×480；记录 fit zoom；调用 zoom in/out；检查比例等价和 mode；进入 fullscreen 等待 `isFullScreen()`；检查 mode、视口尺寸和新 zoom；退出 fullscreen 并再次检查 mode。
- **预期结果**：逆向滚轮后 mode 仍为 ZoomToFit；fullscreen 视口改变时 zoom 重新计算；enter/exit 在 5 s 内完成；退出后 mode 仍为 ZoomToFit。
- **后置条件**：关闭窗口并恢复 `quitOnLastWindowClosed`；记录 enter/exit 响应时间。

### TC-ZOOM-MANUAL-RESIZE / AC-ZOOM-03

- **测试目的**：确认修复只恢复真正回到 fit 的情况，不影响其他手动比例。
- **前置条件**：Cocoa 平台可创建可见窗口；临时 1600×900 PNG 可读；窗口非全屏。
- **输入数据**：先设 ZoomToFit，再只调用一个 zoom in；随后把窗口从 640×480 调整到 1000×800。
- **操作步骤**：加载、设 fit、放大；记录手动比例和空 mode；调整窗口并处理事件；再次读取 mode 和比例。
- **预期结果**：mode 仍为空；手动比例在浮点容差内保持不变，不被重算为 fit。
- **后置条件**：关闭窗口并恢复应用 quit policy。

### TC-IMG-WEBP / AC-LOAD-01

- **测试目的**：验证普通 WebP 仍能打开，覆盖 Qt 失败后的 native fallback。
- **前置条件**：Image I/O WebP UTI 可用；临时目录可写。

- **操作步骤**：通过 `QVImageLoader` 请求图片，等待 `imageReady` 最长 5 s。
- **预期结果**：QImage 非空且为 1×1；`errorData` 不存在。
- **后置条件**：释放临时文件和 loader。

## 5. 执行顺序

按以下顺序执行，任一阶段失败即停止交付判定：

```bash
cmake --build build-fovelle-task --parallel

python3 tests/quality_static.py \
  --build-dir build-fovelle-task --output reports/evidence/static.json
python3 tests/quality_unit_runner.py \
  --binary build-fovelle-task/tests/fovelle_tests --output reports/evidence/unit.json
python3 tests/quality_integration.py \
  --build-dir build-fovelle-task --output reports/evidence/integration.json
python3 tests/quality_fullscreen_system.py \
  --binary build-fovelle-task/tests/fovelle_tests --output reports/evidence/system-fullscreen.json
python3 tests/quality_system_probe.py \
  --app build-fovelle-task/Fovelle.app/Contents/MacOS/Fovelle \
  --runs 3 --hold-seconds 0.8 --output reports/evidence/system.json
```
