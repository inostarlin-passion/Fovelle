## 1. 信息来源与事实边界

已联网检索上游 qView 的 [Issue #864](https://github.com/jurplel/qView/issues/864)。该 issue 的事实描述是：macOS 在打开图片后很快退出时，Open With 菜单的 `QtConcurrent` 后台任务仍可能创建应用图标/QPixmap，应用上下文已销毁后触发 `SIGABRT`。本项目是 Fovelle，代码中的等价路径是 `MainWindow` 的 Open With 异步菜单填充；“等价路径”是基于代码结构的推断，不表示本地仓库拥有上游 issue 的 GitHub 状态。

需求与上游 [Issue #856](https://github.com/jurplel/qView/issues/856) 的“小图片默认按 1:1 查看”描述一致；本规格把它作为本次新增选项的需求背景。Qt 官方文档说明 `QtConcurrent::run()` 任务不能被取消，`QFutureWatcher::waitForFinished()` 用于等待完成，且 QPixmap 相关操作需要存活的 GUI 应用上下文：[QFutureWatcher](https://doc.qt.io/QT-6/qfuturewatcher.html)、[QFuture](https://doc.qt.io/QT-6/qfuture.html)、[QPixmap](https://doc.qt.io/qt-6/qpixmap.html)。

GitHub Release 工作流的 action 版本采用官方仓库当前示例使用的 `softprops/action-gh-release@v3`；本地测试验证工作流契约，不模拟 GitHub 云端发布。[softprops/action-gh-release](https://github.com/softprops/action-gh-release)

文档中的“事实”来自源代码、测试输出或链接的官方资料；“推断”明确标出；“不确定性”集中列出，不把静态契约检查表述为真实云端发布。

## 3. 测试环境、数据与门槛

### 3.1 确定性条件

- 测试命令统一使用 `QT_QPA_PLATFORM=cocoa QT_FATAL_WARNINGS=1`。
- `ScopedOptionValues` 保存并恢复 QSettings，避免测试污染用户配置。
- 图片由测试代码写入临时目录：打开场景为 `32×24` PNG，浏览场景为 `48×36` PNG；窗口可用区域为 `640×480` 级别。
- 策略边界使用 `100×80` 对 `120×100`、等宽边界、单维超限、关闭开关和非 Never 模式。
- 系统资源探针使用 WebP、AVIF 及带方向信息的 WebP/AVIF，每种 3 次独立启动。

### 3.2 性能与资源门槛

| 指标 | 门槛 |
|---|---:|
| 启动平均时间 | ≤ 2.0s |
| 启动 P99 | ≤ 3.0s |
| 启动最大时间 | ≤ 5.0s |
| 重复启动吞吐量 | ≥ 0.5 次/s |
| 归一化 CPU 峰值 | ≤ 100% |
| RSS 峰值 | ≤ 786432 KiB |
| 磁盘 I/O 观测峰值 | ≤ 500 MB/s |
| 网络观测吞吐量（门禁） | ≤ 64 MiB/s |
| 主机网络字节增量（辅助观测） | 记录，不作为进程归因门禁 |
| 打开句柄峰值 | ≤ 512 |
| 网络 socket 峰值 | ≤ 4 |
| 全屏切换平均/P99/最大响应 | 各 ≤ 2000ms |

门槛是本次可重复验证窗口的验收门槛，不是所有硬件、所有图片尺寸或所有 GitHub runner 的性能保证。

## 4. 测试用例规格

### TC-IMG-SMALL-SETTING：Image 设置暴露与持久化

- 测试目的：确认新选项存在于 Settings → Image，默认关闭，勾选后写入 `smallimageoneone=true`。
- 前置条件：Qt Test 已创建 `QApplication`；`ScopedOptionValues` 已备份并设置该键为 false；可构造 `QVOptionsDialog`。
- 输入数据：设置键 `smallimageoneone`，初值 `false`；目标勾选框对象名 `smallImagesOneToOneCheckbox`。
- 操作步骤：构造设置对话框；按对象名查找勾选框；校验文本含 `1:1` 且未勾选；勾选并调用 Apply；读取 SettingsManager。
- 预期结果：勾选框存在、文案正确、初始关闭，Apply 后 SettingsManager 返回 true。
- 后置条件：测试 helper 恢复原始 QSettings 和 SettingsManager 状态。
- 固化代码：`FeatureTests::testSmallImageOneToOneSettingIsExposedInImageOptions`。

### TC-IMG-SMALL-POLICY：边界与 Window 模式判定

- 测试目的：验证策略只依赖开关、WindowResizeMode、图片尺寸和实际 viewport，并覆盖边界。
- 前置条件：可调用 `QVGraphicsView::shouldDisplaySmallImageAtOneToOne` 纯函数 helper。
- 输入数据：图片 `100×80`、viewport `120×100`；等宽 `100×100`；viewport 宽 `99`；图片宽 `121`；开关 false；模式 `WhenLaunching`。
- 操作步骤：分别调用 helper，记录每组布尔结果。
- 预期结果：仅第一组返回 true；等宽、任一维超限、关闭开关、非 Never 均返回 false。
- 后置条件：无持久化副作用。
- 固化代码：`GraphicsViewTests::testSmallImageOneToOnePolicyUsesViewportAndWindowMode`。

### TC-IMG-SMALL-OPEN-BROWSE：打开与浏览双场景

- 测试目的：确认用户补充要求的两个场景都生效，而不是只覆盖首次打开。
- 前置条件：Cocoa Qt Test；开关 true；WindowResizeMode 为 Never；CalculatedZoomMode 为 ZoomToFit；窗口可见；临时目录有两张小 PNG。
- 输入数据：`01-open-small.png` 为 `32×24`，`02-browse-small.png` 为 `48×36`；先打开第一张，再执行 Next。
- 操作步骤：显示 MainWindow；调用 `openFile`；等待 pixmap loaded 和当前路径；断言 ZoomToFit 且 zoom=1.0；调用 `goToFile(Next)`；等待第二路径加载；再次断言 zoom=1.0；关闭窗口。
- 预期结果：打开第一张和浏览到第二张均按 1:1 显示；当前路径顺序正确。
- 后置条件：关闭窗口并恢复 quit-on-last-window-closed 与设置。
- 固化代码：`GraphicsViewTests::testSmallImageOneToOneAppliedWhenOpeningAndBrowsingImages`。

### TC-ISSUE-864-OPENWITH-TEARDOWN：Open With 退出竞态

- 测试目的：验证关闭窗口时后台 Open With 任务不会越过 GUI 生命周期。
- 前置条件：Cocoa Qt Test；临时 PNG；窗口设置为不自动删除，以便在嵌套作用域中明确触发析构；应用保持运行。
- 输入数据：已加载图片路径；显式调用 `MainWindow::requestPopulateOpenWithMenu()`，随后关闭窗口。
- 操作步骤：显示并加载图片；请求 Open With 异步填充；记录时间；离开作用域触发析构；恢复应用退出策略。
- 预期结果：析构在 5 秒内完成；进程无崩溃，worker 结束前已等待；无 QPixmap/QGuiApplication teardown 错误。
- 后置条件：临时图片和窗口对象释放，QSettings/退出策略恢复。
- 固化代码：`FeatureTests::testOpenWithWorkerTeardownContract`。
