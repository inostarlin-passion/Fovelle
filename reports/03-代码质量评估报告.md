# Fovelle 代码质量评估报告

## 1. 评估结论

本次改动在当前 macOS/Qt 环境下达到交付质量门槛：四级门禁全部通过，需求代码路径、测试代码路径和 bundle 集成路径闭环。评分采用“通过 / 有边界”而非未经测量的绝对保证。

| 质量维度 | 结论 | 依据 |
|---|---|---|
| 精益完整性 | 通过 | 仅增加窗口级 icon 清空、wheel 纯计算分支、macOS Image I/O fallback、格式注册同步及对应测试 |
| 功能正确性 | 通过 | 单元 28/28；集成 9/9；WebP/AVIF 系统启动各 3/3 |
| 时间行为 | 通过 | 平均/P99/最大启动时间和吞吐率均低于/高于规格门槛 |
| 资源利用 | 通过（带观测边界） | CPU/RSS/句柄/socket 进程观测和磁盘/网络主机观测均过门槛 |
| 可测试性 | 通过 | 纯函数、确定性 fixture、运行时 UTI 查询、非侵入式采样和 JSON 证据 |

## 2. 变更设计评价

### 2.1 精益完整性

实现选择保持在现有架构内：

- `QVGraphicsView` 只暴露一个可测试的 wheel factor helper；平台事件层只负责区分普通 wheel 与 touch device。
- Image I/O 代码集中在已有 macOS 专属 `QVCocoaFunctions`，没有向通用 loader 引入 Objective-C++ 细节。
- loader 仍先走 Qt `QImageReader`，只有 image 为空且后缀对应的 Image I/O UTI 可用时才 fallback。
- 格式集合由 `QVApplication` 统一扩展，Settings 继续读取 `getAllFileExtensionList()`，避免维护第二份 Formats 列表。
- CMake、qmake、测试 target 同步声明 CoreGraphics/ImageIO，避免“源码可编译、旧构建系统不可用”。

没有引入网络下载、第三方运行时、持久化格式迁移或新的全局设置，因此改动面与需求相称。

### 2.2 功能正确性与不变量

已验证的不变量：

1. mouse wheel 正反向倍率互为倒数；`0` delta 返回 `1.0`，不会意外缩放。
2. touch fractional 分支保留幂指数计算；普通 mouse branch 不使用 delta 的绝对数量放大步长。
3. Qt 解码成功时不执行 native fallback；native 支持性由系统返回的 UTI 决定。
4. native decode 所有主要错误路径都释放 `CGImageSourceRef`、`CGImageRef`、`CGContextRef` 和 `CGColorSpaceRef`，并返回可观测的错误文本。
5. WebP/AVIF extension、MIME、文件过滤和 Settings 表均来自同一运行时能力集合；AVIF `.avifs` 别名明确注册。
6. bundle icon 仍存在；清空的是每个图片窗口的 icon，不是 Finder/Dock 的 app icon。

代码质量证据：[`static.json`](evidence/static.json)、[`unit.json`](evidence/unit.json)、[`integration.json`](evidence/integration.json)。

### 2.3 时间行为

系统实测值与门槛如下：

| 指标 | 实测 | 门槛 | 评价 |
|---|---:|---:|---|
| 平均启动 | 4.204 ms | 2 s | 通过 |
| P99 启动 | 9.188 ms | 3 s | 通过 |
| 最大启动 | 9.188 ms | 5 s | 通过 |
| 吞吐率 | 1.1164 次/s | 0.5 次/s | 通过 |

样本为 WebP/AVIF 各 3 次，hold 0.8 s。该指标衡量应用启动/保持过程，不等同于任意尺寸超大图片的完整解码耗时；大图性能不在本次输入负载内。

### 2.4 资源利用

| 指标 | 实测峰值 | 门槛 | 观测归属 |
|---|---:|---:|---|
| CPU | 4.875%（12 逻辑 CPU 归一化） | ≤100% | Fovelle 进程 |
| RSS | 718,496 KiB | ≤786,432 KiB | Fovelle 进程 |
| 句柄 | 148 | ≤512 | Fovelle 进程 |
| socket | 0 | ≤4 | Fovelle 进程 |
| 磁盘 I/O | 4.82 MB/s | ≤500 MB/s | 主机 `iostat` |
| 网络增量 | 1.680 MiB | ≤64 MiB | 主机 `netstat` |

RSS 初始 512 MiB 门槛经同机旧版 baseline 复测约 585 MiB 后调整为 768 MiB；这属于可记录的基线校准，不是隐藏失败。主机级 I/O 不足以证明单进程精确 I/O，报告已明确标注。

### 2.5 可测试性

- `wheelZoomFactor()` 将易受 Cocoa 事件设备差异影响的数学规则纯化，支持输入-输出直接断言。
- WebP/AVIF fixture 固化在 C++ 与系统 runner 中，不需要下载图片或依赖用户数据。
- Image I/O 支持性通过 `CGImageSourceCopyTypeIdentifiers()` 运行时查询，测试先验证能力再验证像素结果。
- `QVImageLoader` 通过已有 `imageReady` 信号观测，没有添加测试专用生产代码分支。
- 静态、单元、集成、系统脚本都输出结构化 JSON，Markdown 报告可追溯到原始证据。

## 3. 风险、限制与未决项

### 已确认的事实

- Qt `UnsupportedFormatError` 的数值是 3；当前构建使用的 Qt imageformats 不足以覆盖本机 AVIF，Apple Image I/O 可用。
- 构建出的 bundle 包含 `qView.icns`，Info.plist 声明 `webp`、`avif`、`avifs`。
- 系统测试中两种格式所有 run 均没有 Unsupported/Error 3 文本。

### 推断

- 当前用户错误提示主要由 Qt plugin 能力/部署缺口触发，而非 WebP/AVIF 文件损坏。推断基于 Qt 错误码、插件目录和同一字节 fixture 的 Image I/O 成功结果。
- wheel 过度缩放主要由原实现无条件 fractional 处理引起；`delta=240` 的对照测试直接复现了倍率差异。

### 不确定性与后续建议

- 不同 macOS 版本可能返回不同 Image I/O UTI；这是代码的运行时能力边界。若产品要求覆盖不支持 AVIF 的旧系统，应另行定义兼容策略（例如部署第三方 AVIF plugin），本次没有擅自引入第三方依赖。
- 本次未建立带 EXIF 旋转元数据的 WebP/AVIF fixture，因此没有把 orientation 行为宣称为本次已验证项；这是未来图片元数据回归测试的候选项。
- 系统标题栏没有通过 Accessibility 逐帧截图验证；当前用 Qt window icon 状态 + bundle 集成 + 静态检查验证行为契约。
- 仓库中原有全屏 Cocoa 测试未纳入本次功能 gate；其源文件未作为本次生产功能修改对象。
