## 2. 设计与实现评估

### 2.1 精益完整性

实现只处理产生标题栏图标的两个窗口状态：

1. 构造主窗口时调用 `setWindowIcon(QIcon())`，形成明确的窗口级空 icon。
2. `clearTitlebarIcons()` 在 native handle 可用时调用 `handle->setIcon(QIcon())` 和 `handle->setFilePath(QString())`。
3. 在显示窗口、文件状态变化和标题栏显隐切换后调用同一 helper，避免把清理逻辑复制到多个分支。
4. 没有删除 `qView.icns`、`CFBundleIconFile` 或文件关联，也没有增加设置项、线程、持久化字段或运行时依赖。

因此变更与需求边界相称：窗口标题栏身份被清空，应用 bundle 身份仍保留。

### 2.2 功能正确性与不变量

测试和代码共同支持以下不变量：

- 新窗口的 QWidget icon 为空。
- 有效图片加载完成后，`MainWindow::windowFilePath()` 和 native `QWindow::filePath()` 为空。
- 图片仍被标记为 loaded，标题仍含输入文件名。
- 文件切换以及标题栏隐藏/显示导致的 native window 状态变化不会恢复 icon 或 file path。
- bundle executable、`.icns`、identifier 和 WebP/AVIF 文件关联不变。
- `clearTitlebarIcons()` 对空状态重复执行不会产生额外外部状态；它只向同一 native handle 写入相同的空值。

实现入口：[`src/mainwindow.cpp`](../src/mainwindow.cpp#L725)。测试入口：[`tests/tst_qviewtests.cpp`](../tests/tst_qviewtests.cpp#L507)。

## 4. 官方依据与事实分层

### 4.1 事实

- Qt 明确规定 macOS 标题栏 window icon 只有在 file path 设置时才显示。[Qt QWindow](https://doc.qt.io/qt-6/qwindow.html#icon-prop)
- Qt 明确规定 macOS `windowFilePath` 会设置窗口 proxy icon。[Qt QWidget](https://doc.qt.io/qt-6/qwidget.html#windowFilePath-prop)
- Qt 源码显示 `QWindow::setFilePath` 和 `QWindow::setIcon` 都转发到平台窗口实现。[Qt qwindow.cpp](https://raw.githubusercontent.com/qt/qtbase/dev/src/gui/kernel/qwindow.cpp)
- Apple 明确规定 `representedURL` 为空时没有 document icon。[Apple NSWindow](https://developer.apple.com/documentation/appkit/nswindow/representedurl)
- 本项目最终测试证据显示所有当前门禁 `passed=true`。

### 4.2 推断

- 清空 native file path 是去掉 document proxy 的必要且充分的主要状态操作；清空 native icon 用于防止窗口重建后恢复窗口级 icon。
- 未更改 bundle icon 是保持 Finder/Dock 身份的最小兼容策略。

### 4.3 不确定性与风险

1. 没有使用 Accessibility API 对标题栏进行逐像素识别；如果产品需要视觉回归金标准，应在具备 Accessibility 权限的 macOS runner 增加 AXProxy/截图断言。
2. 测试在单一 macOS/Qt 组合和小型目标负载上完成；旧系统、超大图、多窗口、长时间运行需要单独建立基线。
3. RSS 距门槛约 53.9 MiB，当前通过但应在 CI 中持续监控。

## 5. 维护建议

- 任何未来把图片路径再次写入 `QWindow::setFilePath()` 或 `QWidget::setWindowFilePath()` 的改动必须同时更新 AC-02/AC-04 并重新执行 Cocoa 系统 runner。
- 若改变 bundle icon、Info.plist 或文件关联，应保留 AC-05 回归并重新确认“应用身份”和“窗口标题栏身份”仍然分离。
- 在 CI macOS runner 上保留四阶段顺序和 JSON evidence，避免只凭人工目测判定标题栏图标。
