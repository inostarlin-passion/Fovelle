# Fovelle GitHub Actions CI 修复代码质量评估报告

## 1. 评估对象与结论

评估对象：WebP/AVIF 方向加载修复、clang-tidy CI 配置、对应的静态/单元/集成/系统测试代码及审计证据。

结论：在 macOS 15.7.7、Qt 6.11.1、Cocoa、arm64 本地环境下，精益完整性、功能正确性、时间行为和可测试性均达到本次验收阈值。远程 GitHub runner 的修复后重跑仍是未完成的外部验证，不在本报告中虚构为绿色。

## 2. 可审计证据链

### 2.1 基线事实

- [Build Fovelle run 32107116589](https://github.com/inostarlin-passion/Fovelle/actions/runs/32107116589)：WebP loader 断言实际 `QSize(2x3)`、期望 `QSize(3x2)`。
- [Checks run 32107116541](https://github.com/inostarlin-passion/Fovelle/actions/runs/32107116541)：clang-tidy 输出 `Error: no checks enabled.`。
- 失败提交为 `3a22d1b692d7be6fdb6a344f1cdf98bbd75e6102`；当时没有关联 Pull Request，故按 push workflow 追踪。

### 2.2 根因与修复映射

| 观察 | 根因判断 | 修复/证据 |
|---|---|---|
| loader 得到未旋转尺寸 | 旧代码先 Qt read，只有空图才 ImageIO；非空未变换结果绕过方向感知 decoder | [`src/qvimageloader.cpp`](../src/qvimageloader.cpp) 改为支持格式 ImageIO-first，Qt fallback；ST-06、I-03、`TC-ORI-*` |
| clang-tidy 无启用项 | 工具安装和 CMake wiring 存在，但没有 `-checks`/`.clang-tidy` 选择检查 | [`.clang-tidy`](../.clang-tidy)、ST-18、I-15 |
| 方向变换语义 | Apple ImageIO 的 transform key 负责方向/宽高比 | [Apple ImageIO 文档](https://developer.apple.com/documentation/imageio/kcgimagesourcecreatethumbnailwithtransform?changes=__5) |
| Qt fallback 语义 | Qt reader 提供自动变换设置和错误路径 | [Qt QImageReader 文档](https://doc.qt.io/qt-6/qimagereader.html) |
| tidy 选择语义 | clang-tidy 检查由 `-checks` 或配置文件控制 | [LLVM clang-tidy 文档](https://clang.llvm.org/extra/clang-tidy/index.html) |

“Qt 在该 CI 版本一定不会执行任何方向变换”不是直接证据，而是对日志结果和旧控制流的最小解释；实现不依赖这一绝对假设，而是让 Apple ImageIO 在受支持格式上成为明确主路径。

## 3. 四项质量要求评估

### 3.1 精益完整性：通过

- 生产改动集中在一个读取函数：新增后缀能力判断、native-first、空图 fallback 和错误合并。
- 未重写 SVG、动画、多帧选择和其他格式路径；因此改动边界与故障边界一致。
- CI 配置只新增必要的 `.clang-tidy`，复用现有 workflow 和 `build.sh --tidy`，没有引入新的检查框架或发布依赖。
- 测试代码只增加根因契约 ST-06/ST-18、I-03/I-15；方向 fixture 和既有测试复用，不重复生成测试数据。

静态证据中 ST-01～ST-18 全部通过；其中 ST-06 防止 decoder 顺序回退，ST-18 防止 tidy 配置重新变成空集合。详见 [`static.json`](evidence/static.json)。

### 3.2 功能正确性：通过

不变量和副作用如下：

|---|---|---|
| WebP/AVIF 方向 fixture 最终尺寸为 3x2 | `testImageLoaderAppliesWebpOrientation`、`testImageLoaderAppliesAvifOrientation` | 通过 |
| ImageIO 失败仍可由 Qt 读取 | `testImageLoaderLoadsWebpWithImageIOFallback`、AVIF 对应测试 | 通过 |

### 3.4 可测试性：通过

- **系统化生成**：每个 AC 都映射到一个 TC，测试规格书为每个 TC 固化目的、前置条件、输入、步骤、预期和后置条件。
- **确定性控制**：方向图像使用源码内置 base64 fixture；全屏使用合成 Qt key event；系统探针固定 `runs=3`、`hold-seconds=0.8`。
- **非侵入式观测**：质量脚本通过退出码、Qt test 输出、源码契约、compilation database、App bundle 和进程级指标观测，不在生产代码中加入测试开关。
- **外部输出可重放**：所有阶段写入 JSON，字段包含 `pass`/`passed`、实际值、期望值、返回码和限制说明。
- **桌面隔离**：Cocoa 系统脚本串行执行，减少共享窗口焦点和全屏状态造成的非确定性。

每个原子测试用例都显式包含“测试目的、前置条件、输入数据、操作步骤、预期结果、后置条件”六个审计字段，集中记录在 [`01-测试规格说明书.md`](01-测试规格说明书.md)；本报告只引用结果，避免把执行说明复制成第二份易漂移的测试定义。

## 5. 风险、边界与改进建议

| 项目 | 评估 |
|---|---|
| 远端环境差异 | 本地 Qt 6.11.1/macOS 15.7.7 与失败 run 的 Qt 6.8.x/macOS 14 不同；需推送后观察同一 GitHub runner。 |
| clang-tidy 版本差异 | 本地验证使用 Homebrew LLVM 22.1.8；配置只启用低噪声、稳定的检查集合，并未将普通 warning 强制升级为 error。 |
| clang-format 版本差异 | 本地默认 PATH 无 clang-format；ST-01 使用 clean compile fallback。基线 GitHub format job 已通过，修复提交应由远程 workflow 再确认。 |
| native decoder 失败回退 | fallback 保持可用，但若未来 ImageIO 对新格式返回“错误但非空”的图像，需要增加更强的语义校验；当前日志和需求范围不要求扩大改动。 |
| 资源指标 | RSS、主机 I/O 和网络指标用于回归门禁，不应替代专用 profiling 或隔离主机基准。 |

## 6. 最终评价

当前实现以最小控制流修复解决了已观测的两个 CI 阻断点，并以源码契约、方向回归测试、真实 Cocoa 测试、clang-tidy 可执行验证和 JSON 证据形成闭环。代码层面的本地质量门禁通过；远端 Actions 只有在修复提交发布并重新运行后，才可完成最终环境一致性确认。
