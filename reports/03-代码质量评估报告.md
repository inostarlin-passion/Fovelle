## 3. 实现设计评估

### 3.1 快捷键：单一来源和可配置性

[`src/shortcutmanager.cpp`](../src/shortcutmanager.cpp) 将 Full Screen 默认值设置为 `Qt::Key_Return`。[`src/mainwindow.cpp`](../src/mainwindow.cpp) 和 [`src/mainwindow.h`](../src/mainwindow.h) 删除了独立的 Return/数字键盘 Enter `QShortcut`，因此进入全屏的行为由已有 ActionManager/QAction 链路统一控制。

质量收益：

- 设置为空时没有第二条隐藏路径；
- 用户自定义 Space 等快捷键不需要修改窗口代码；
- 默认值、持久化值和 QAction 运行时值可在同一个测试中核对。

该设计符合 Qt [QShortcut](https://doc.qt.io/qt-6/qshortcut.html) 的快捷键对象模型，也避免将 [`QKeySequence::FullScreen`](https://doc.qt.io/qt-6/qkeysequence.html) 的平台标准值误当成本需求的固定 Enter 默认值。

### 3.2 标题栏文本：复用现有字段计算

[`MainWindow::buildWindowTitle`](../src/mainwindow.cpp) 复用现有文件详情、分辨率、文件大小和缩放计算，只改变 Practical/Verbose 的拼接顺序：

- Practical：文件名 → 序号/总数；
- Verbose：文件名 → 序号/总数 → 宽×高 → `formatBytes` 文件大小 → 一位小数百分比。

没有新增标题状态缓存或第二套格式化器，减少了状态同步和格式漂移风险。测试使用真实临时文件、实际文件大小和实际视图缩放，不用硬编码文件大小来“自证”。

### 3.3 Theme：设置、原生外观和画面填充分层

实现分成三个清晰层次：

1. [`src/settingsmanager.cpp`](../src/settingsmanager.cpp)：Theme 枚举默认 Light，并为旧 `titlebaralwaysdark`/`bgcolor*` 保留一次性迁移；新设置库不再暴露旧控件对应键。
2. [`src/qvoptionsdialog.ui`](../src/qvoptionsdialog.ui) 与 [`src/qvoptionsdialog.cpp`](../src/qvoptionsdialog.cpp)：Theme ComboBox 只有 Light/Dark 两项，删除 Background color 和 Titlebar always dark UI/同步代码。
3. [`src/qvcocoafunctions.mm`](../src/qvcocoafunctions.mm) 与 [`src/mainwindow.cpp`](../src/mainwindow.cpp)：Theme 通过 AppKit Aqua/DarkAqua 设置原生标题栏；画面区域在 QWidget 绘制路径中使用 Preview 参考色 `#969696` 或 `#212121`，棋盘格分支优先。

这种分层使主题变化可被非侵入式观察：测试从 QWindow 读取有效外观名，从窗口截图扫描画面区域颜色。Apple 的 [显式选择 App 外观](https://developer.apple.com/documentation/AppKit/choosing-a-specific-appearance-for-your-macos-app)以及 [Aqua](https://developer.apple.com/documentation/appkit/nsappearance/name-swift.struct/aqua?language=objc)/[Dark Aqua](https://developer.apple.com/documentation/appkit/nsappearance/name-swift.struct/darkaqua?language=objc)文档为原生桥接提供了平台依据。

### 3.4 兼容迁移的边界

旧设置迁移保留了明确选择深色标题栏或旧默认深色背景的用户偏好；旧的任意自定义背景色无法无损映射到二元 Theme，因此迁移到 Light/Dark 是有界推断，不伪装成颜色等价迁移。该边界在测试规格和完成报告中明确记录。

## 4.1 Light Theme 背景差异的根因分析

- 截图事实：`/Users/inostarlin/Downloads/Snipaste_2026-08-18_14-15-24.jpg` 的 Preview 图像外侧留白区域采样为 `(150,150,150)`，即 `#969696`。
- 代码事实：原实现的 `MainWindow::settingsUpdated()` 把 Light Theme 的 `customBackgroundColor` 设为 `QColorConstants::White`；`paintEvent()` 直接用该成员填充未被图像覆盖的画面区域。
- 平台事实：`QVCocoaFunctions::setWindowTheme(..., Aqua, ...)` 只设置 AppKit 原生窗口外观；它不会替换 Qt 自定义 `paintEvent()` 已经选择的画布填充色。Qt 文档说明自定义控件的背景由绘制/背景角色决定，AppKit 外观不自动改写该自绘区域。
- 根因结论：Light Theme 的标题栏外观映射正确，但画面背景常量错误；错误不在图像解码或缩放链路。
- 修复：将 Light Theme 常量改为 `QColor("#969696")`，并把 `testThemeAppliesNativeAppearanceAndViewportBackground` 的 Light 断言改为精确检测 `#969696`；Dark Theme 和棋盘格行为保持不变。

## 8. 风险、限制与改进建议

1. Apple 文档确认 Preview 使用灰色图像/PDF 背景，但没有给出固定 RGB；用户提供截图的留白区域采样为 `#969696`，当前用 Aqua/DarkAqua 和 `#969696`/`#212121`实现可重复的参考映射。若要把“同色”提升为所有环境的逐像素要求，应在指定 macOS 版本、指定 Preview 设置下提交新的参考截图和采样值。
2. AppKit 原生标题栏颜色由系统外观和窗口状态共同影响，测试核对原生 appearance name，比单点像素更稳定；这不能代替视觉回归截图。
3. 早期并行 Cocoa 试验出现焦点争用导致的假失败；正式脚本已按共享桌面状态串行执行。持续集成环境应保留该约束。
4. 当前 `clang-format` 不可用，ST-01 使用成功的 CMake 编译回退；若 CI 提供固定版本 clang-format，可再增加格式化差异门禁。
