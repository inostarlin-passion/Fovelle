# 全屏快捷键与 macOS 全屏退出跳变代码质量评估报告

**文档编号**：QR-FS-2026-08-17
**评估对象**：Fovelle 0.1.0 本次全屏行为修改
**输入依据**：[测试规格说明书](01-测试规格说明书.md)、[测试完成报告](02-测试完成报告.md)及 `reports/evidence/*.json`
**总评**：通过；性能和资源结论限定在本机、低负载、有限样本门禁内。

## 1. 评估范围和方法

评估聚焦以下质量要求：

- 精益完整性：只增加需求所需的入口快捷键、单一状态恢复和验证代码。
- 功能正确性：检查输入、前置条件、状态转换、幂等性、图片内容和几何副作用。
- 时间行为：测量全屏状态确认的平均、P99、最大响应时间和确认吞吐率；另测 App 启动指标。
- 资源利用：观测进程 CPU、RSS、句柄、socket，以及主机磁盘/网络指标。
- 可测试性：固定输入、确定性环境、非侵入式采样、机器可读证据和有界超时。

依据链包含 Qt 窗口状态和快捷键文档、Qt Cocoa 平台实现、Apple AppKit 文档及本地 Git 历史：[Qt QWindow](https://doc.qt.io/qt-6/qwindow.html)、[Qt QShortcut](https://doc.qt.io/qt-6/qshortcut.html)、[Qt Cocoa 源码](https://github.com/qt/qtbase/blob/dev/src/plugins/platforms/cocoa/qcocoawindow.mm#L3573-L3690)、[Apple `toggleFullScreen(_:)`](https://developer.apple.com/documentation/appkit/nswindow/togglefullscreen%28_%3A%29)、[上游 `remove shownormal`](https://github.com/inostarlin-passion/Fovelle/commit/6e5297df9602e391c3b8b001f4f83ef7ca0f711d)。

## 2. 变更审查

### 2.1 入口设计

[`src/mainwindow.cpp`](../src/mainwindow.cpp) 增加两个 `QShortcut`：

- `Qt::Key_Return`：主键 Enter。
- `Qt::Key_Enter`：数字键盘 Enter。

两者都设置 `setAutoRepeat(false)`，并调用同一个入口 lambda。lambda 先检查 `!windowState().testFlag(Qt::WindowFullScreen)`，因此在全屏状态下重复 Enter 不会触发退出。成员声明位于 [`src/mainwindow.h`](../src/mainwindow.h)。这满足需求且没有引入新的状态机、定时器或跨类依赖。

### 2.2 退出路径设计

[`MainWindow::toggleFullScreen()`](../src/mainwindow.cpp) 的退出分支现在只执行：

```cpp
setWindowState(storedWindowState);
```

没有先执行 `showNormal()`。Qt 文档把 `showNormal()` 和设置 `Qt::WindowNoState` 都定义为普通窗口状态请求；结合 Qt Cocoa 退出全屏需要等待原生通知的实现，重复请求会在一个异步过渡上叠加第二次状态应用。当前修复选择单一请求，和本地历史中删除 `showNormal()` 的上游修复方向一致。

该解释中“重复请求导致可见跳变”是基于事实的推断，不是 AppKit 文档直接承诺的因果结论；代码通过静态单请求检查和几何回归测试验证其结果。

## 4. 实测时间和资源评估

### 4.1 全屏状态确认

来自 [system-functional.json](evidence/system-functional.json)：

| 指标 | 实测 | 门槛 | 结论 |
|---|---:|---:|---|
| 平均响应 | 21.43 ms | ≤ 2000 ms | 通过 |
| P99 响应 | 46 ms | ≤ 2000 ms | 通过 |
| 最大响应 | 46 ms | ≤ 2000 ms | 通过 |
| 状态确认吞吐 | 46.67 次/s | ≥ 0.5 次/s | 通过 |

指标定义是“合成快捷键或 shortcut 请求到 Qt 报告目标状态”的耗时；退出全屏后的 macOS 动画仍可能在状态确认后继续运行，因此不能把该指标解释为逐帧视觉完成时间。

### 4.2 App 启动与资源

来自 [system.json](evidence/system.json)：

- 启动平均 6.27 ms，P99 11.48 ms，最大 11.48 ms，吞吐 1.11 次/s。
- CPU 峰值按 12 个逻辑 CPU 归一化为 5.52%，RSS 峰值 502032 KiB，句柄峰值 143，网络 socket 峰值 0。
- 磁盘空间使用率 63.79%，主机磁盘 I/O 峰值 11.59 MB/s，主机网络字节增量 0.92 MiB。

全部 S-01～S-12 通过。上述指标是 5 次启动同一 PNG 的小负载样本，不能外推到大图片、连续幻灯片、超高分辨率显示器或长时间运行。

## 5. 可测试性与可维护性

### 确定性控制

- 每个图片测试在 `QTemporaryDir` 生成固定尺寸、固定颜色 PNG。
- 每个窗口显式设为 `Qt::WindowNoState`，显式 `raise/activateWindow`，并等待可见、激活和图片加载。
- 原生全屏过渡后统一等待 2 s，再发起下一次状态变化，避免把异步动画重叠误判为功能失败。
- 所有等待均有上限；没有无限 sleep 或人工介入才能通过的断言。

### 非侵入式观测

- 全屏响应只在测试代码输出 `FS_METRIC`，不修改生产状态机。
- 资源探针从外部进程通过 `ps`、`lsof`、`iostat`、`netstat` 采样，不向应用注入统计逻辑。
- 系统功能 runner 以外部进程启动编译后的 Qt 测试二进制，并检查返回码、测试名和指标。

### 审计和复现

四阶段 runner 均输出 JSON：

- [static.json](evidence/static.json)
- [unit.json](evidence/unit.json)
- [integration.json](evidence/integration.json)
- [system-functional.json](evidence/system-functional.json)
- [system.json](evidence/system.json)

结果包含命令产物、退出码、测试套件、原始输出尾部、指标、门槛和限制说明。代码中的 TC-FS 注释为每个功能用例保留了目的、前置条件、输入、步骤、预期和后置条件。

## 6. 风险、限制和后续验收

事实层面的限制：当前环境没有 `clang-format`；磁盘/网络探针为主机级；系统功能测试发送的是 Qt 合成事件；没有真实 UI 逐帧录像。

推断层面的风险：不同 macOS/Qt 版本可能改变 Cocoa 全屏动画时序；外接显示器、Mission Control 空间和窗口标题栏隐藏状态可能暴露未覆盖的组合。

建议的人工补充：在目标发布机打开一张普通图片，按 Enter 进入全屏，等待动画结束后按 Esc，确认图片内容、窗口位置和尺寸稳定；用左上角按钮重复一次作为对照。若该人工路径仍出现跳变，应记录 macOS 版本、Qt 版本、显示器布局和窗口几何后再扩大兼容性测试。
