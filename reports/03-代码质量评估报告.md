# Fovelle 代码质量评估报告

## 1. 评估结论

当前 macOS 15.7.7 / Qt 6.11.1 环境下，本次实现满足需求并通过全部质量门禁。结论按“证据支持的通过”表达，不把一次小负载测量扩大解释成所有图片尺寸和所有 macOS 版本的绝对保证。

| 质量维度 | 结论 | 审计依据 |
|---|---|---|
| 精益完整性 | 通过 | 复用既有 Image I/O bridge、loader fallback 和 graphics view 状态，不引入第三方运行时或持久化迁移 |
| 功能正确性 | 通过 | 单元 32/32；集成 9/9；方向像素/尺寸、真实 fullscreen 状态和手动缩放不变量均有测试 |
| 时间行为 | 通过（目标负载） | 启动平均/P99/最大/吞吐和 fullscreen 响应指标全部过门槛 |
| 资源利用 | 通过（带观测边界） | 进程 CPU/RSS/句柄/socket 与主机磁盘/网络观测均过门槛 |
| 可测试性 | 通过 | 纯计算 helper、固定方向 fixture、Qt 属性/信号观测、四类 JSON evidence |

## 2. 设计与实现评估

### 2.1 精益完整性

实现范围与需求相称：

- 方向修复限定在 macOS 专属 [`qvcocoafunctions.mm`](../src/qvcocoafunctions.mm)，没有把 Objective-C++ 依赖扩散到通用 loader。
- 原生读取仍由运行时 `CGImageSourceCopyTypeIdentifiers()` 判断能力；Qt 成功时不重复执行 fallback。
- `CGImageSourceCreateThumbnailAtIndex` 的最大像素尺寸取源图属性长边，因此只是借用 Image I/O 的元数据变换能力，不额外改变现有完整分辨率意图。
- 缩放修复只新增两个 optional 状态字段和一个纯浮点比较 helper；没有增加新的 settings、线程或定时器。
- 既有 `MainWindow`、文件注册表、CMake/qmake 结构不变；Settings → Formats 继续读取统一扩展集合。

### 2.2 功能正确性与不变量

已由代码与测试共同支持的不变量：

1. WebP EXIF RightTop 的 2×3 原始像素经过 native decoder 后成为 3×2，并且四角颜色位置正确。
2. AVIF `irot` fixture 的 native 和 loader 路径均成为 3×2，并且不产生 `ErrorData`。
3. 普通 wheel 的正向 1.25 与反向 0.8 互为倒数；touch fractional 的 240 delta 仍为 1.5625。
4. ZoomToFit 在 inverse wheel 后恢复 mode；fullscreen 改变 viewport 时触发新的 fit 计算。
5. 非 fit 的真正手动比例在 resize 后 mode 仍为空，zoom level 不被自动重算。
6. 换图、显式关闭 calculated mode、选择 OriginalSize 时清空旧的 fit 候选，避免跨图或显式用户选择被隐式覆盖。
7. Image I/O source/options/thumbnail/context/color space 在成功和失败路径均释放；loader 只在 image 为空且 native UTI 可用时接管。
8. bundle icon 资源保留，窗口级 icon 清空不影响 Finder/Dock 身份。

| 磁盘空间 | 63.8825% | ≤95% | 主机文件系统 |

RSS 距 768 MiB 门槛约 43.8 MiB，当前是通过但仍应作为后续大图/多窗口压力测试的观察项。此前同负载复测曾观测到 788,480 KiB，runner 正确判定 S-09 失败；随后同参数复测峰值为 758,128 KiB 和本次最终复核的 741,584 KiB，说明该指标受 macOS/后台状态影响。此前较低的 512 MiB 门槛与同机 Qt/Cocoa 启动 baseline 冲突，因此本次使用 768 MiB，并在 runner 注释、JSON threshold 和报告中显式记录。

### 2.6 可测试性

- `wheelZoomFactor()` 和 `zoomLevelsEquivalent()` 是无副作用 helper，可直接生成边界输入并断言输出。
- 方向 fixture 固化为 base64；WebP 直接断言像素，AVIF 直接断言方向变换后的尺寸，避免依赖图片查看器截图或人工判断。
- fullscreen 用真实 `MainWindow::toggleFullScreen()`、`isFullScreen()`、viewport size 和 zoom mode 观测；没有模拟一个与生产逻辑不同的 fake fullscreen。
- loader 通过现有 `imageReady` 信号非侵入式观测；系统 probe 通过 `ps`/`lsof`/`iostat`/`netstat` 采样，不改生产代码。
- 四阶段 runner 统一把命令、返回码、suite、指标、阈值和 pass flags 写入 JSON，报告可由原始 evidence 复核。

## 3. 事实、推断和不确定性分层

### 3.1 事实

- Qt 文档说明 `QImageReader::setAutoTransform(true)` 应用变换元数据。[Qt QImageReader](https://doc.qt.io/qt-6/qimagereader.html)
- Apple 文档说明 `kCGImageSourceCreateThumbnailWithTransform` 负责方向变换且默认不启用。[Apple Image I/O](https://developer.apple.com/documentation/imageio/kcgimagesourcecreatethumbnailwithtransform?changes=__5)
- 当前代码测试证明带 EXIF/`irot` fixture 的 native 输出方向正确；最终系统 probe 的 12 次启动均无 Error 3。
- 原版 qView 源码包含普通 wheel 与 touch device 的不同 delta 处理路径。[qView source](https://raw.githubusercontent.com/jurplel/qView/master/src/qvgraphicsview.cpp)

### 3.2 推断

- 方向 bug 是 Qt 自动变换与 native fallback 元数据路径不一致造成的；不是 UI 坐标系本身先验错误。
- fullscreen 偏小是 fit mode 丢失造成的 resize 不重算；不是 fullscreen 本身必然改变用户缩放意图。
- 保存最近 calculated level 并用容差恢复，是覆盖“逆向滚轮回到 fit”且不侵入真正手动缩放的最小状态模型。

### 3.3 不确定性

- 旧 macOS 的 Image I/O UTI 集合、AVIF 解码能力和具体方向属性支持可能不同；本实现选择运行时能力查询而非静态保证。
- 小 fixture 的启动资源峰值不能代表超大图、动画图、多窗口和长期运行；这些需要单独的压力测试规格。
- 主机 I/O counter 可能受后台进程影响；当前结果只用于本次目标负载的门禁。

## 4. 风险与后续建议

1. 增加超大 WebP/AVIF、动画 AVIF、不同 EXIF 1～8 方向和带 alpha 的长期回归集合。
2. 在 CI 的真实 macOS runner 上重复资源测试，并建立 Qt/Cocoa 版本基线，避免 RSS 门槛只依赖单机校准。
3. 若产品要覆盖不支持 `public.avif` 的旧 macOS，应另行评估部署第三方 AVIF plugin；本次不引入额外依赖。
4. 如果未来引入多屏异 DPI fullscreen 场景，应补充屏幕切换、DPI 变化与 fit mode 的组合测试。
