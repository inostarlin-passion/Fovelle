# Fovelle 代码质量评估报告

**文档编号**：QR-FOVELLE-2026-08-17
**评估对象**：Fovelle 0.1.0 macOS-only 修改
**依据**：[测试规格说明书](01-测试规格说明书.md)、[测试完成报告](02-测试完成报告.md)、[unit.json](evidence/unit.json)、[integration.json](evidence/integration.json)、[system.json](evidence/system.json)
**总评**：通过；性能/资源结论属于本机小负载门禁，不是生产 SLA

## 1. 评估方法

本评估把代码质量要求转换为五个维度，并同时检查：

- 需求覆盖：品牌、图标、窗口行为、更新器、Bundle、CI 和 macOS-only 清理是否形成闭环。
- 行为正确性：输入、前置条件、状态转换和副作用是否由单元/集成测试覆盖。
- 时间与资源：系统探针是否提供平均值、P99、最大值、吞吐和资源峰值。
- 可测试性：测试条件是否可确定性控制，观测是否非侵入式，结果是否可重复审计。
- 变更边界：是否避免改动文件名、类名、函数名、变量名和不必要的项目结构。

信息来源采用了从仓库事实到构建产物，再到 Qt、CMake、Apple Bundle 和 GitHub Release 官方文档的链式核验：

- Qt last-window 语义：[QGuiApplication](https://doc.qt.io/qt-6/qguiapplication.html#lastWindowClosed-signal)
- Qt shortcut 语义：[QShortcut](https://doc.qt.io/qt-6/qshortcut.html)
- CMake Bundle 标识：[MACOSX_BUNDLE_GUI_IDENTIFIER](https://cmake.org/cmake/help/latest/prop_tgt/MACOSX_BUNDLE_GUI_IDENTIFIER.html)
- CMake Bundle 图标：[MACOSX_BUNDLE_ICON_FILE](https://cmake.org/cmake/help/latest/prop_tgt/MACOSX_BUNDLE_ICON_FILE.html)
- Apple 图标资源键：[CFBundleIconFile](https://developer.apple.com/documentation/bundleresources/information_property_list/cfbundleiconfile)
- GitHub Release 接口：[List releases](https://docs.github.com/en/rest/releases/releases#list-releases)
- 上游来源核验：[`jdpurcell/qView`](https://github.com/jdpurcell/qView) 页面标记为 [`jurplel/qView`](https://github.com/jurplel/qView) 的 fork，许可证页面为 GPLv3。

## 3. 设计与实现评估

### 3.1 精益完整性

实现采用了少量明确的变更点：

- `src/main.cpp` 集中设置 Fovelle organization/application identity。
- `src/qvapplication.cpp` 设置运行时 PNG 图标和 `setQuitOnLastWindowClosed(true)`。
- `src/mainwindow.cpp` 让 Escape 在全屏分支退出全屏、在普通分支关闭窗口，并把窗口标题基线改为 Fovelle。
- `src/qvaboutdialog.cpp/.ui` 固定用户要求的 About 内容、Fovelle 仓库链接和 jdpurcell/qView 来源署名。
- `README.md` 删除原末行，并增加 jdpurcell/qView 与 jdpurcell 署名。
- `src/updatechecker.h/.cpp` 只替换更新 API/下载地址为本项目仓库。
- `CMakeLists.txt`、`qView.pro`、`dist/mac/*.plist`、工作流仅保留 macOS 构建链。
- 删除明确的 Linux/Windows 源文件、资源和部署脚本；未重命名 qView 原有文件、类、函数、变量和翻译文件。

这种拆分把品牌显示逻辑、Bundle 身份、平台边界和测试证据分别固定，避免通过全局字符串替换改变历史版权文本或项目结构。

### 3.2 功能正确性与不变量

关键不变量如下：

| 不变量 | 实现位置 | 验证 |
|---|---|---|
| 运行时应用图标非空 | `QVApplication` 构造函数 | U-01、I-06 |
| identity 在创建窗口前已设置 | `main.cpp` | U-02、I-03 |
| 退出策略恒为 true | `QVApplication` 构造/设置刷新 | U-05、I-03 |
| Escape shortcut 恒为 `Qt::Key_Escape` | `MainWindow::shortcutsUpdated()` | U-06、U-07、I-03 |

| updater 不访问旧仓库 | `UpdateChecker` 常量 | I-02 |

About 页使用 HTML 链接承载两个 GitHub 地址，但通过纯文本提取验证可见内容保留用户给定块并追加 qView 来源署名；网站没有填入旧地址。README 的旧末行已移除，且最后一行为署名句。

### 3.5 可测试性

可测试性设计达到以下目标：

- **确定性输入**：用户 PNG 被复制后用字节比较和 SHA-256 固定；单元图像测试使用临时目录和程序生成的 32×32 图片。
- **确定性环境**：测试显式设置 `QT_QPA_PLATFORM=cocoa`、`QT_FATAL_WARNINGS=1`，测试构建关闭自动更新联网。
- **分层测试**：QtTest 负责对象/状态行为；Python 集成脚本负责源码、Bundle、CI、资源和 CTest；系统探针只通过外部进程工具观测。
- **非侵入式观测**：没有向生产代码注入测试分支或性能计数器；使用 `ps`、`lsof`、`iostat`、`netstat` 和 Bundle plist。
- **可重复输出**：每阶段返回码与 JSON `passed`/`pass_flags` 同步，原始输出和限制说明均保留。

## 5. 风险、残余项与改进建议

### 已知不确定性

1. **物理 Esc 输入**：当前单元测试核对 Escape key binding 并直接激活同一 Qt shortcut 分支；这避免 Cocoa 原生全屏自动化偶发崩溃/丢键，但没有模拟真实用户键盘硬件。建议在目标机器执行一次全屏/普通窗口 Esc 手工回归。
2. **最后窗口退出**：代码设置与 Qt 官方语义一致，单元测试验证策略和关闭状态；若要做进程级黑盒验证，可增加受 Accessibility 权限约束的 macOS UI automation。
3. **更新网络**：本次没有对 GitHub Release 做真实下载，避免测试依赖外部发布状态；发布前应使用隔离测试 Release 做一次端到端验证。
4. **签名/公证**：构建链可生成 `.app`，但本次没有 Apple Developer 证书和 notarization 凭据，因此不能声称发布包已签名公证。
5. **本地化目录**：翻译文件名按项目结构约束保留；关键品牌、About 文本和 URL 已同步到翻译源，尚未进行各语言的语言质量人工审校。

### 改进建议

- 发布前增加一个不依赖系统辅助功能权限的 Cocoa 测试 harness，用独立子进程观察最后窗口关闭后的自然退出。
- 在 CI 中加入已签名/未签名 Bundle 的 `codesign --verify` 和 `spctl` 检查（如果项目提供证书）。
- 若恢复翻译构建，执行 `lupdate/lrelease` 并逐语言确认 About、更新器、Welcome 和设置提示均显示 Fovelle。
- 在代表性大图和长时运行负载下重复系统探针，单独建立生产 SLO，不复用本报告的本机门槛。

## 6. 事实、推断与结论

### 事实

- 最终 unit/integration/system JSON 均为返回码 0 且 `passed=true`。
- Bundle 实际包含 Fovelle 可执行文件、Fovelle Bundle ID、0.1.0 版本和由指定 PNG 生成的 qView.icns 文件。
- 工作区活动实现中未发现 Windows/Linux 平台 token；明确的非 macOS 文件和目录已移除。
- GitHub 页面事实：`jdpurcell/qView` 标记为 `jurplel/qView` 的 fork，仓库的许可证页面显示 GPLv3；本地 Git 历史显示多条提交与该 GitHub 账号关联。

### 推断

- 在已声明的构建环境和低负载下，代码满足用户列出的五项质量要求，并且没有发现必须返工的功能缺陷。
- 通过保留原文件/类/函数/变量命名而只改变用户可见身份，满足“项目结构不变”约束的意图。
- “部分提交来源于 jdpurcell/qView”是基于用户声明、GitHub fork 关系和本地作者历史的归属判断；没有对每个文件逐行做版权分界，因此不扩大为“全部代码由 jdpurcell 编写”。

### 结论

本次修改达到可交付质量：需求闭环、三阶段测试通过、证据可审计。剩余事项均已在“已知不确定性”中明确，不应被误读为已完成的签名、公证、物理 UI 或真实 Release 升级验证。
