# Fovelle 代码质量评估报告

## 1. 评估结论

在当前 macOS 15.7.7 arm64、Qt 6.11.1、AppleClang 17 环境中，Fovelle 达到本次验收定义的五项质量目标：

| 质量目标 | 结论 | 依据 |
|---|---|---|
| 精益完整性 | 通过 | 使用完整上游依赖闭包，保留现有 Fovelle 入口，只增加必要的 bundle/事件/测试适配 |
| 功能正确性 | 通过（平台边界单独标记） | 21 个 QtTest、CTest、Git/产物检查和 5 次 GUI bundle 启停均通过 |
| 时间行为 | 通过本地代理门槛 | 平均 `0.006742 s`、P99 `0.012091 s`、最大 `0.012091 s`、吞吐 `1.18337 runs/s` |
| 资源利用 | 通过可采集项 | 归一化 CPU `8.433%`、RSS `287712 KiB`、句柄 `104`、socket `0`、磁盘空间 `63.625%`、host I/O `8.14 MB/s` |
| 可测试性 | 通过 | 固定 fixture、确定性 QSettings 控制、非侵入式 ps/lsof/iostat/netstat 观测、JSON 证据和 CTest 入口 |

“通过”只适用于本报告定义的验收边界。用户没有提供时间和资源的数值规范，因此这些数值门槛是工程推断；host 级磁盘/网络计数也不等价于应用独占计费。

## 2. 变更结构与精益性

### 2.1 合并策略

工作簿列出的提交来自 [jdpurcell/qView](https://github.com/jdpurcell/qView)，且提交之间存在新 loader/movie/enumerator 架构依赖。最终使用双父合并：

- 第一父：本项目 `8014b07`，保留 Fovelle 的 macOS 定位、应用身份和已有文档打开修复。
- 第二父：完整上游头 `1748058632574831516f75e642ef28b7e3cc3e63`。
- 合并提交：`1be85e129e5ed06d6760cf9dadf9fc68fb61cbf1`。
- 后续质量 harness 提交：`c2a94a1eb7fb0ef977abf5a519565c2529d4fe4f`。

这避免了把依赖闭包拆成若干不相容 cherry-pick，也使 `git merge-base --is-ancestor` 能审计每一个工作簿 SHA。提交标题和主题可从 [上游提交列表](https://github.com/jdpurcell/qView/commits/master/) 以及测试规格中的逐项链接复核。

### 2.2 必要实现范围

- `src/qvimageloader.*`：预加载优先级、缓存、错误和析构安全。
- `src/qvmovie.*`：动画帧读取、精确定时、速度修正。
- `src/qvfileenumerator.*`：目录兼容文件枚举和按需刷新。
- `src/qvapplication.*`：Launch Services 文件事件路径/URL 入队、空输入 guard、事件循环异步派发。
- `src/mainwindow.cpp`：首次启动欢迎弹窗延迟并让文件事件优先。
- `CMakeLists.txt`/`tests/CMakeLists.txt`：将全部新增依赖纳入 CMake 构建与 CTest。
- `dist/mac/Info.plist.in`、部署脚本和 CI：统一 Fovelle bundle identity 与产物路径。
- `tests/quality_*.py`：只做测试编排和证据保存，不侵入产品运行时代码。

没有为未要求的服务层、缓存数据库、远程 telemetry 或额外抽象引入新代码；这符合精益性目标。

## 4. 时间行为评估

### 4.1 测量方法

`tests/quality_system_probe.py` 启动同一 `Fovelle.app` 和同一 ICNS 5 次；以 `ps` 首次观察到 PID 的时间作为启动响应代理，每 50 ms 采样一次并在 0.8 s 后可控终止。P99 使用 nearest-rank，吞吐为运行次数除以总 elapsed。

### 4.2 结果

| 指标 | 结果 | 推断门槛 | 评估 |
|---|---:|---:|---|
| 平均启动代理 | `0.0067421916 s` | `≤2 s` | 通过 |
| P99 | `0.0120912920 s` | `≤3 s` | 通过 |
| 最大 | `0.0120912920 s` | `≤5 s` | 通过 |
| 吞吐 | `1.1833699365 runs/s` | `≥0.5 runs/s` | 通过 |

限制：启动代理不是完整的用户感知“打开图片完成”时间；图片异步加载的有限时间通过 QtTest 的 5 s `QTRY` 断言验证。没有用户给出的正式 P99/SLO，因此不能把上述门槛称作产品合同。

## 5. 资源利用评估

### 5.1 进程级

| 指标 | 结果 | 推断门槛 | 评估 |
|---|---:|---:|---|
| 原始进程 CPU 峰值 | `101.2%` | 归一化 ≤ `100%` | 通过；12 个逻辑 CPU 上归一化为 `8.433%` |
| RSS 峰值 | `287712 KiB` | `≤524288 KiB` | 通过 |
| 句柄峰值 | `104` | `≤512` | 通过 |
| 网络 socket 峰值 | `0` | `≤4` | 通过 |

原始 `%CPU` 按每逻辑 CPU 100% 的 macOS `ps` 语义记录；归一化是为了避免把多线程进程超过 100 的正常表示误判为整机满载。

### 5.2 主机级

| 指标 | 结果 | 推断门槛 | 评估 |
|---|---:|---:|---|
| 磁盘空间占用 | `63.6251869%` | `≤95%` | 通过 |
| `iostat` 磁盘 I/O 峰值 | `8.14 MB/s` | `≤500 MB/s` | 通过 |
| `netstat` 接收增量 | `530292 bytes` | 未给出 | 记录，不作应用独占结论 |
| `netstat` 发送增量 | `549786 bytes` | 未给出 | 记录，不作应用独占结论 |

`iostat` 和 `netstat` 只能在当前权限和 macOS 工具可用范围内提供主机级观测；背景同步、网络活动或其他进程会影响它们。因此“存储 I/O/网络 I/O 持续受控”的严格进程级证明仍需要 DTrace、Endpoint/Performance API 或隔离机器，当前报告不掩盖这一不确定性。

## 8. 风险、技术债与建议

| 风险 | 严重度 | 当前状态 | 建议 |
|---|---|---|---|
| Finder/Dock/Open With 原生 UI 未自动点击 | 中 | 源码契约、编译和间接启动已通过 | 在 macOS GUI CI 或人工验收中增加 `osascript`/截图回归 |
| 多帧 ICC/APNG 视觉转换未做像素级端到端断言 | 中 | 转换函数和动画更新调用链已覆盖 | 准备带 ICC profile 的 APNG/GIF fixture，断言每帧 colorSpace/像素 |
| 磁盘/网络只有 host 级计数 | 中 | 记录并明确限制 | 在隔离 runner 使用进程级 I/O API 或 DTrace |
| qmake 入口文件仍名为 `qView.pro` | 低 | 保留上游兼容入口，TARGET 已为 Fovelle | 若停止上游兼容，可另行迁移为 `Fovelle.pro`，需独立变更 |
| Qt 翻译默认关闭以保证离线确定性 | 低 | `FOVELLE_BUILD_TRANSLATIONS=OFF` 默认可构建 | 发布流水线按需开启并验证 Qt Linguist/翻译资源 |

## 9. 事实、推断和不确定性分界

### 事实

- Git、构建、QtTest、CTest、qmake 和探针的退出码/数值如本报告所列。
- 上游提交主题与链接见 [测试规格说明书](01-测试规格说明书.md)，提交来源是 [jdpurcell/qView](https://github.com/jdpurcell/qView)。
- 证据文件由 runner 在当前工作树 `reports/evidence` 生成。

### 推断

- 性能/资源门槛是为本次验收补充的工程代理，不是题目中隐含的正式 SLO。
- 事件队列与欢迎弹窗的时序修复能降低 Launch Services 冷启动竞态，是基于代码路径和测试结果的工程推断。

### 不确定性

- 未在所有 macOS 版本、显示器色彩空间、用户 defaults、第三方 Open With app 和真实 Dock UI 上重复。
- 未执行真实网络下载、公证、签名和发布 artifact 安装。
- host 级 I/O 不能精确归因到 Fovelle。
