# Fovelle 双图对比模式设计

仓库基线为 `31f2918`。「依据」来自源码或官方文档。「设计决策」是首版拟采用的产品与工程规则。「待验证」需要原型、实机或性能数据。本文的性能数字均为初始验收目标。

## 1. 问题、前提与约束

用户需要在同一窗口查看两张图，通过同步缩放和同步平移快速检查相近区域，必要时独立调整，再交换左右位置。两张图可能来自不同目录，具有不同的尺寸、宽高比、方向和动态范围。联动需在这些差异下可预测，也要允许用户手动对齐裁切不同的照片。

- **依据。** 产品面向 macOS 15 及以上，发布工作流使用 Qt 6.11.2，CMake 仍保留 Qt 5 回退。现有打开对话框虽接收多选，文件仍逐项打开。窗口的标题栏遮挡、缩略图、导航和全屏回调目前都以单个视口为中心。 [产品说明](../README.md#L3) · [发布工作流](../.github/workflows/release.yml#L80) · [Qt 构建配置](../CMakeLists.txt#L51) · [文件选择](../src/qvapplication.cpp#L204) · [窗口构造](../src/mainwindow.cpp#L273)
- **设计决策。** 已成功显示的本地静态文件作为固定参考图 A，另一张本地静态文件作为可更换的对比图 B。文件身份与左右位置分开。保留已有的方向、色彩及静态矢量路径。旋转和镜像以进入单图时已有的方向为基础，首版对比中只调整查看位置与倍率。自动配准、叠加和时间轴同步留给后续需求。
- **约束。** 兼容现有单图入口和设置。对比状态属于当前窗口。保存单图会话时使用 A 的路径和进入对比前的查看状态，重启按原有会话格式恢复。联动产生的输入成本应与几何更新相关，图片像素的解码、上传和再细化应由换源或画质需求触发。

## 2. UI 与操作规则

```text
 [✓ 同步缩放]  [✓ 同步平移]  [交换左右]  [退出对比]
 参考 · A.jpg               48% │ 对比 · B.jpg   [更换 ▾]   37%
                                │
           左侧画布              ┃           右侧画布
```

| 场景 | 行为 |
| --- | --- |
| 进入与选图 | 「视图 → 双图对比」在当前本地静态图已提交、无待处理的单图打开请求时可用。进入即显示 A 和空栏，停止幻灯片，两项同步默认开启。A 沿用进入时的缩放模式或手动视图，按新宽度约束。B 可通过「选择对比图」、列头「更换」或拖入 B 所在列的单个本地文件选取。文件选择器取消时保留当前状态。 |
| 布局与无障碍 | 初始等宽，每列最小内容宽 240 个逻辑像素，顶部控件必要时换行。分隔线拖动时显示位置指示，松手后调整宽度，双击恢复等宽，焦点在分隔线时用方向键调整。列头显示角色、文件名、倍率及加载状态，长文件名提供完整路径提示。活动列有可见焦点标记，VoiceOver 同时读出角色与左右位置。加载成功或失败只播报一次。 |
| 指针与键盘 | 点击或在画布开始有效手势时激活该列，`Tab`、`Shift+Tab` 按当前从左到右的顺序访问。画布获焦时方向键用于平移。已有缩放快捷键和菜单按活动列分发，提供「适合窗口」及「100%」。现有适合／100% 切换按活动列决定目标，现有「填满窗口」和自定义百分比也按缩放开关分发。自定义百分比在各目标列的共同倍率范围内取可用值。为联动和交换注册可配置的菜单动作。更换或移除 B 时保留合理焦点，空栏中的缩放快捷键不触发 A。 |
| 交换左右 | 两列均有已提交图时可用，包括旧 B 仍显示的替换阶段。交换对调画面和列头，保持屏幕上的分隔位置。焦点跟随原图，等宽时原画面位置和倍率随图移动。不等宽时，适合或填满模式按新宽度重算，手动模式按新几何投影期望中心。交换先结束画布输入序列，后续惯性尾部由旧序列消费。 |
| 退出与其他入口 | `Esc` 优先由原生对话框处理，其次退出对比，再按原规则处理全屏或关窗。退出恢复 A 在进入前的缩放模式、倍率与中心，按当前单图尺寸重新投影。对比期间收起单图缩略图和前后导航，停用单图换图快捷键、重命名、删除及幻灯片。普通「打开」和 Finder 打开若最终指向该窗口，在确认文件请求后退出对比并沿用原打开流程。 [现有 Esc 分发](../src/mainwindow.cpp#L451) · [菜单动作分发](../src/actionmanager.cpp#L605) |

鼠标拖动、滚动条、分阶段滚轮和原生手势各自从起始控件获取归属。跨越分隔线只更改指针位置，源列持续到对应序列结束，惯性沿用滚轮归属。无阶段滚轮按单事件命中分发。分阶段的开始和结束事件即使没有位移也参与归属，原生捏合流中交错的平移事件按各自类型处理。画布输入转换沿用现有鼠标、触控板和修饰键映射。窗口失活、全屏过渡、换图提交或交换时停止旧序列，迟到的更新一直消费到结束或下一有效起始。macOS 实机需核对滚轮与原生手势的实际投递，尤其是惯性期间换栏。 [现有滚轮与手势实现](../src/qvgraphicsview.cpp#L778) · [原生手势入口](../src/qvgraphicsview.cpp#L3076) · [Qt 滚轮阶段](https://doc.qt.io/qt-6.11/qwheelevent.html#phase-prop) · [Qt 原生手势序列](https://doc.qt.io/qt-6.11/qnativegestureevent.html)

## 3. 联动、边界与相机状态

两个开关即时生效于下一次用户操作。已有倍率和位置保持，用户可先分别调整，再开启联动。两图均就绪时才有跟随列。布局修正、滚动条反馈、原生回调和加载提交只更新自己的视口。缩放附带的锚点补偿归属缩放，同步平移开关只控制显式平移。Lightroom Classic 的官方交互也提供共同缩放、单图缩放和交换，以下联动数学规则由 Fovelle 自行定义。 [Lightroom Classic 对比视图](https://helpx.adobe.com/lightroom-classic/desktop/viewing-photos/browse-compare-photos.html)

### 相对缩放与锚点

- 联动时两列应用同一个倍率因子。令当前倍率为 `zᵢ`，该列可用范围为 `[loᵢ, hiᵢ]`。先求共同因子范围 `[max(loᵢ/zᵢ), min(hiᵢ/zᵢ)]`，把请求因子限制到该范围后，分别乘本列当前倍率。独立时仅使用源列范围。80% 与 40% 同收 1.25 倍，得到 100% 与 50%。若 6400% 与 3200% 再收到放大请求，两列都保持原值，回缩一档即同时响应。这个取舍保留用户设好的倍率比，遇限后仍可关闭同步继续单栏放大。
- 缩放前按源列可用画布构造归一化锚点 `q=(x/宽,y/高)`，再分别投到两列当前可用画布。指针跨栏时先限制在起始列的画布内。每列保留自己锚点下的图像内容，落在留白时复用现有最近可行锚点投影。键盘、菜单或关闭光标缩放时用各列中心。滚动条出现或消失后按最终画布作一次局部修正。 [现有缩放计划](../src/qvgraphicsview.cpp#L1782) · [Qt 视口映射与整数滚动条](https://doc.qt.io/qt-6.11/qgraphicsview.html#centerOn)
- 「适合窗口」与「100%」是绝对命令，按缩放开关应用到一列或两列。适合模式按本列无滚动条的可用范围等比完整容纳并居中，沿用小图适合策略。填满模式同样按列计算，允许裁切。100% 按现有「一对一像素」偏好换算，开启时栅格源像素与设备像素 1:1，矢量以文档逻辑尺寸为准。首版沿用 1%–6400% 手动区间，超长图允许适合倍率低于 1%，手动下限取 1%、当前适合倍率及本列当前倍率的最小值，使布局变化后仍可平滑从低倍率放大。区间扩展仅用于对比视口。 [倍率常量](../src/qvnamespace.h#L22) · [现有适合计算](../src/qvgraphicsview.cpp#L2196) · [DPR 修正](../src/qvgraphicsview.cpp#L3045) · [Qt 高 DPI](https://doc.qt.io/qt-6.11/highdpi.html)

### 平移与布局恢复

1. 在每个轴上，用同一份几何快照先计算源列**约束后、取整前**实际可移动距离 `Δs`。源列没有可滚动范围或已经到边界时，该轴位移为零。
2. 若同步平移开启，目标列请求 `Δt = Δs × T / S`，其中 `S`、`T` 为两列该轴上已定向、已缩放的图像尺寸。对目标再独立约束。源列可移动 100 个逻辑像素、两列渲染宽分别为 2000 和 1200 时，目标请求 60。若源列只剩 20 的行程，目标只请求 12。目标先触边时，源列仍可继续，任何触边的超量都丢弃，反向输入立刻有效。
3. 复用现有范围与滚动条换算，内部保留浮点位置。滚动条最终取整，不用整数回读作为另一列的新输入。拖滚动条的用户意图应来自控件操作，程序写入的 `valueChanged` 仍可刷新画面但不参与联动。 [现有平移约束](../src/scrollhelper.cpp#L11) · [视口滚动监听](../src/qvgraphicsview.cpp#L269)

手动视图保存倍率和定向图像坐标中的**期望中心**，布局提交时得到受边界限制的实际中心。仅真正改变该列相机的用户查看操作才更新其期望中心。因换栏、分隔线、DPR 或全屏变化而产生的裁剪只改变实际中心，所以同一几何下连续交换两次可恢复先前构图，即使中间一度触边。适合与填满视图每次布局重算。当两张图构图或裁切不同时，联动只能维持用户建立的近似构图。

### 双视口与窗口状态

| 现有依据 | 设计决策 |
| --- | --- |
| `getViewportPosition()` 直接从主视口推导窗口遮挡。视口适合尺寸使用 `maximumViewportSize()`，避免滚动条显隐反过来改变适合倍率。 [窗口遮挡](../src/mainwindow.cpp#L2645) · [视口可用范围](../src/qvgraphicsview.cpp#L2673) | 由窗口计算标题栏可见区域，每列用自身视口原点换算遮挡与可用矩形，控件占据的区域只扣一次。所有缩放、平移和原生裁切读同一版布局。窗口挂载固定的水平 `QSplitter`，从单图起就持有 A，进入比较才创建 B。同一父级内重排两个列容器，并按屏幕左右还原列宽，退出销毁 B，A 恢复单图填充。 [Qt 分隔器重排](https://doc.qt.io/qt-6.11/qsplitter.html#insertWidget) |

| 原生渲染器以内容代次过滤回调，切换 HDR 源时现有单图路径可先露出新图的 Qt SDR 底图，且换源会同步排空编码队列。 [原生换源](../src/qvcocoafunctions.mm#L3386) · [原生首帧揭示](../src/qvcocoafunctions.mm#L3768) | 比较的换源路径需先准备可用呈现内容，再发布新列状态。将交换实现为已有源的布局更新，避免触发换源或等待编码队列。Qt 与原生层按列裁切，工具栏在其外。持久图层独立于 Metal drawable，Metal 帧与 Qt 绘制可能跨合成时点，实机需验证无串栏与旧帧泄露。 [Apple Metal 图层呈现](https://developer.apple.com/documentation/quartzcore/cametallayer/presentswithtransaction) |

### B 的异步状态

B 同时维护已提交内容和至多一个待选目标，状态以会话代次、B 绑定、选择序号、文件版本识别。原生呈现另携带内容代次与当前布局所需的几何版本。换栏只变更布局映射。若布局变化导致已准备的视口尺寸不再合用，复用已解码内容按新几何准备，保留该文件请求。

| 事件 | 可见结果和提交条件 |
| --- | --- |
| 选择、预检与解码 | B 空栏显示占位。已有 B 时保留它及其联动，列头显示待加载文件。B 走独立加载实例，复用原有读取、方向、色彩和文件版本能力，停用目录枚举、预读和动图播放。后台检查文件身份、格式及预算，读取前后核对版本。若读取路径延迟取像素，需要持有稳定数据源或使用经验证的预览，以待原型核实。 |
| 候选准备完成 | 可提交的第一帧可以是符合色彩要求的完整帧，或显式标记的「预览」或「SDR 预览」。在一次界面状态提交中同时切换 B 的图像身份、列头和相机，B 以适合模式居中。最终画质或原生层就绪时只更新同一图像的画质和标记，沿用用户期间调整的相机。 |
| 换图失败或最终画质失败 | 候选尚未提交时保留旧 B，给出重试或重选。预览已提交而细化失败时保留当前预览，继续显示画质标记和重试入口。尺寸缩小的预览以源图几何计算查看状态，高倍时显示源像素细节暂不可用。移除 B 会释放其资源并将槽位恢复为空。 |
| 重新选择、移除、退出、关窗 | 先使旧序号或会话失效，再撤销订阅、取消任务和清理层。只有当前版本的选择可改变列头或画面。取消未能立即停止的后台工作仍受全局并发约束，资源待实际释放后再归还预算。 |

现有 `QVImageLoader` 只保留一个前台待处理请求，`QVImageCore::loadPixmap()` 又耦合目录、错误画面和动图初始化。因此保留通用解码与像素提交部分，比较的候选与错误状态在覆盖旧 B 之前判定。相同文件仅在版本、解码规格及色彩语义相符时共享不可变数据。文件版本检查在后台执行，GUI 提交使用经验证的已读快照，原生延迟读取另按上表约束。 [加载器状态](../src/qvimageloader.h#L109) · [版本验证入口](../src/qvimageloader.cpp#L128) · [文件身份](../src/fileversion.h) · [主图提交](../src/qvimagecore.cpp#L260)

## 5. 性能与降级顺序

- **交互。** 先以逐事件更新相机、按后端合并绘制为基线。缩放锚点可能移动，边界截断也依赖输入顺序，未经等价验证的乘积或位移求和会改变结果。交互期间复用已解码表面或矢量预览，结束时按当前两列可见区域细化。分隔线默认用位置指示并在松手时提交真实宽度，实测空间允许后再考虑实时重分配。 [Qt 分隔器拖动行为](https://doc.qt.io/qt-6.11/qsplitter.html#opaqueResize-prop)
- **并发。** 对比引入的重型换图流水线全应用同时最多一个。等待队列按窗口合并，仅保留最新选择，多窗口公平轮转。另有轻量文件探测，使用现有异步设施。已派发且无法停止的任务及原生准备保留其资源配额。A 继续持有已显示内容，比较期间暂停本窗口可取消的邻图预读。关闭或退出从界面立即脱离，后台资源按实际完成归还。 [工作队列](../src/asyncwork.cpp#L13) · [解码派发](../src/qvimageloader.cpp#L512)
- **内存。** 原型先采用每窗口 512 MiB 的可计量图像资源准入阈值，并以 512 MiB 作为全应用比较功能的增量占用阈值。窗口额度覆盖 A、旧 B、新 B、临时缓冲和 CPU/GPU 表面，全应用额度覆盖对比引入的新资源。同一作用域内可证明共享的分配只计一次。两项均为待校准的准入阈值，实际进程峰值独立采集。尺寸、行跨度、通道深度和表面数量使用防溢出估算。读出、原生上传及大小变化需要额外缓冲时先预留，兑现后登记实际值，旧表面和取消任务释放后再归还。未知上界的路径只在有受限替代方案时准入。默认保持已显示的 A。
- **降级。** 依次回收可再生缓存、选择原生视口尺寸回退、采用解码器能保证上界的预览。Qt 的 `setScaledSize()` 可能全尺寸解码后再缩放，不能凭输出尺寸分配额度。只有 SDR 预览可用时明确标记并始终采用一致的色彩转换。仍不足时保留当前画面，提示更换文件，或主动移除旧 B 后重试。对比期间原生持久 HDR 表面受共享额度约束。 [Qt 解码缩放](https://doc.qt.io/qt-6.11/qimagereader.html#setScaledSize) · [现有 HDR 持久表面上限](../src/qvcocoafunctions.mm#L3247)
- **容量算例。** 两张 24 MP 的 RGBA8 图各留一份约 183 MiB，替换期间三份约 275 MiB。在总画布 1200 × 800 逻辑像素、2× DPR 下，两列各有三个 RGBA16F drawable 时合计约 88 MiB。换图窗口在这两类资源上的示例合计约 363 MiB，尚需为解码临时缓冲、行对齐、原生备份和纹理留空间。 [现有 Metal 格式和缓冲数](../src/qvcocoafunctions.mm#L2223)

## 6. 验收、实施顺序与发布条件

| 检查 | 可复现的通过条件 |
| --- | --- |
| 几何与联动 | 四种开关组合均以异尺寸、异宽高比和已定向图片复测。共同因子在上限时保持倍率比；缩放本应可行的锚点误差 ≤ 1 逻辑像素。平移以实际源位移传递，覆盖任一列先触边、轴无范围、亚像素输入与反向回拖。用不等宽窗格连续交换两次，覆盖中间投影触边的情况，最后回到原视图。 |
| 窗口与输入 | 就近记录原生和 Qt 序列，覆盖零增量首尾、分隔线跨越、滚动惯性、原生菜单、VoiceOver、分隔线键盘操作、多窗口、全屏和跨屏。交换或换图后旧序列无写入，一次 Esc 只执行一个动作。退出成功恢复 A 和原快捷键。 |
| 加载与错误 | 用可控完成顺序测试慢 C、换栏、新请求 D、关闭、同路径替换和损坏文件。按图像标记、列头、请求版本逐帧核对。解码或 GPU 准备失败时，旧 B 或已提交预览可继续查看。旧任务结束后资源可回收。 |
| 色彩与合成 | 在 macOS 15 与 26、1×／2×、单屏与跨屏上检查 SDR＋SDR、SDR＋HDR、HDR＋HDR、透明及矢量。用不同颜色和角点标记的图片检查交换时无错误列、黑帧或跨栏残留。监测混排 HDR 时各列动态范围和亮度，并确认重复换源不积累表面。 |
| 性能 | 在同一台 Apple Silicon Mac、固定 60 Hz 屏幕及相同画布上先测单图基线。对本机 24 MP JPEG 的冷、热应用缓存分别重复至少 30 次，记录系统文件缓存状态。连续移动且几何持续变化时，以漏掉的刷新机会 ≤ 5%、输入到两列可见 P95 ≤ 33 ms 为初始目标。交换到两列正确可见 P95 ≤ 33 ms，源解码启动数为 0。冷缓存从 B 请求到首个可用画面 P95 ≤ 800 ms，同时记录最终画质就绪时间和峰值占用。大 TIFF、RAW 和双 HDR 单独报告完整画质与降级结果。 |

测量以事件 ID、内容代次和布局版本串起输入、GUI 提交、原生提交及可见画面。双栏呈现用同一版本中较晚可见的一列计时。若一列已触边或无需重绘，以画面上已有的正确状态计入。Metal 采用现有 drawable 呈现诊断，Qt 或持久 CA 层采用可观察的窗口帧采样。应用层绘制完成只用于诊断。检查未显示的中间版本时，以显示周期内最后有效输入和采样画面做匹配，避免把主动合并的小步都算成漏帧。独立测试慢盘和内存压力，不把硬件时延阈值加入常规 CI。 [现有 Metal 呈现日志](../src/qvcocoafunctions.mm#L4325) · [Apple drawable 呈现回调](https://developer.apple.com/documentation/metal/mtldrawable/addpresentedhandler(_:)) · [现有测试入口](../tests/CMakeLists.txt)

实施顺序为双视口原型 → 相机与输入 → 候选加载与预算 → 原生全屏、混合后端及实机验收。双视口原型需先证明 A 的单图几何兼容和原生裁切正确。首版默认开放须通过双 HDR、异步换图不串栏和可测的内存准入要求。原型若出现原生渲染限制，先确定适用格式及标记规则，再决定发布范围。

## 7. 迭代检索与回溯核验

| 轮次 | 依据 | 推断与回查 |
| --- | --- | --- |
| 窗口与输入 | 回查源码的视口遮挡、滚动约束，Qt 官方文档确认分隔器可重排已有项、滚轮阶段可以零位移，原生序列可交错。 | 每列独立计算可用区域，归属按序列管理。手算共同倍率区间及源端只剩 20 时的 12 像素跟随，分别验证饱和和反向动作。 |
| 换图与呈现 | 回查主图加载器只跟踪一个前台请求，以及 Metal 原生路径的 generation、drawable 呈现回调和 Qt SDR 底图行为。 | 若顺序是「请求 C → 交换 → 请求 D → C 回调 → 退出 → D 回调」，两个回调都不提交。若 D 在退出前通过检查，应提交到交换后的 B 所在列。尺寸变化只重做依赖几何的呈现准备。 |
| 容量与可观测性 | 回查持久 HDR 阈值、drawable 数和 Qt 缩放解码行为，并按三份 RGBA8 与两栏表面复算容量。 | 同时管控窗口和全应用占用，按可见画面定义延迟。峰值还会受解码器、CI 缓存和系统合成影响。 |

**待验证。** macOS 是否在某些手势序列中向两条输入路径投递同一位移、保留旧 B 时能否在准入预算内准备不同后端的新 B、延迟取像素的原生源是否在换图过程中保持稳定身份、双 EDR 的色调映射及可观察的双栏呈现差值，均需原型或实机数据。512 MiB、帧时延及真实分隔线拖动选择在测得数据后复审。
