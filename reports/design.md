# 视口底部缩略图条设计

## 目标与首版范围

用户浏览同一目录的图片时，把指针移到视口底部就能认出当前图片及其前后邻居，点击缩略图直接切换。面板内可通过滚轮或横向手势浏览目录，浏览位置与当前图片分开。切图完成后，缩略图条以交叉淡入淡出重新居中。缩略图条覆盖在图片上，随指针进入和离开淡入淡出，主图的可用视口、缩放锚点、平移位置和滚动范围均沿用原有计算。

首版默认开启底部悬停，适用于普通窗口和全屏。“视图 → 自动显示缩略图”只控制悬停，按应用记住选项。“视图 → 聚焦缩略图”提供按需打开和键盘访问。有效目录内至少有两张图，且当前已成功显示的文件能定位到该列表时才展示。首次扫描期间等待结果，空窗口、单图目录、加载错误和 URL 下载临时目录沿用原有画面。缩略图条支持相邻预览、滚动浏览目录和跳转。拖拽重排、多选和磁盘缓存留待后续需求。

缩略图条以已提交的主图和目录快照为准。当前发布配置固定按名称升序、关闭目录循环，并隐藏已被目录过滤规则排除的文件。首版继承这些规则，保留循环算法用例用于验证底层行为。 [枚举和排序](../src/qvfileenumerator.cpp) · [设置迁移](../src/settingsmanager.cpp)

四条约束贯穿布局、输入和解码：

| 容易遗漏的情况 | 对用户可见的规则 |
| --- | --- |
| 切图尚未完成，或者缩略图先于主图解码完成 | 同目录切图时中心对应已提交的主图，请求中的目标保留自己的位置并显示等待状态。切换基目录时立即收起旧条。 |
| 重命名、删除、同路径替换、切目录 | 位置会重用。按压、焦点和解码结果按目录与文件身份验证，过期输入取消。 |
| 原生菜单、手势、滚动条、AppKit 全屏过渡 | 每段输入由起始控件持有。覆盖层显隐或渲染路径切换不会把一次点击拆给两个控件。 |
| 大图、慢盘、多个窗口同时解码 | 悬停先显示占位，后台任务受数量和内存预算约束。邻图预览允许降级，显式打开沿用主图流程。 |

## 布局与视觉

- 以 `QVGraphicsView::viewport()` 的水平中心为锚点。计算视口实际可用底边并避开原生遮挡和滚动条，已经由布局扣除的滚动条空间只计算一次。两侧以可用空间较小的一边确定对称宽度，避免滚动条出现时中心偏移。条底距可用底边 14 pt，视口两侧至少留 12 pt。
- 默认单格 144 × 104 pt，间距 8 pt，面板内边距 8 pt，圆角 10 pt。先按标准尺寸选可放下的最大奇数槽位数，上限为 9 和 `2 × (图片数 - 1) + 1` 中较小的值。标准尺寸至少需要 488 pt 的对称宽度才能放下 3 槽，否则改用 112 × 80 pt。紧凑尺寸至少需要 392 pt。仍不足 3 槽或可用高度小于 160 pt 时隐藏。
- 槽位 `k` 的中心为 `viewportCenterX + k × (cellWidth + gap)`，`k = 0` 表示浏览位置。初次呼出和切图提交时以当前项为中心。沿用目录顺序，负偏移在左，正偏移在右。滚动可以移开当前项，条内的内容在面板范围内裁切。关闭目录循环时，越界槽位留空。开启时按目录取模，按距离从近到远占位，同距离先放右侧，每个列表项仅显示一次。5 槽且关闭循环时，首张显示 `[空] [空] [当前] [下一张] [下两张]`；两图循环时显示 `[空] [当前] [另一张]`。
- 图片按原始宽高比完整放入格内，透明图在格内使用低对比底纹。浅色和深色主题各用对应的半透明底色，首版采用纯色合成。系统开启“减少透明度”时改用同主题的实底。当前格用 2 pt 高对比描边，焦点用外框，悬停用背景变化，等待切换的目标用静态标记。格子尺寸固定，占位、成功和失败状态共用一套几何。文件名通过悬停提示和无障碍名称提供，递归目录同名时附上相对父目录。 [Apple 减少透明度](https://developer.apple.com/documentation/appkit/nsworkspace/accessibilitydisplayshouldreducetransparency)
- 现有“没有上一张／下一张”提示在条显示时移到条上方，间隔 8 pt。滚动条和系统控件始终优先，缩略图格优先于左右导航按钮及主图快捷区，面板空白可穿透。标题栏、滚动条和窗口外区域不会触发悬停。

## 触发、动效与输入

所有阈值以逻辑点计算。触发带为可用视口最下方 28 pt，覆盖可用宽度。显现后的保留区包括触发带、面板、面板到触发带之间的垂直空隙，并向面板两侧各放宽 8 pt。进入和离开依据实际视口坐标判断，指针在视口和覆盖控件之间转移时仍按同一坐标重算。只接受实际落在当前活动窗口上的指针事件，视口矩形与 Dock 或其他窗口的几何重叠不会单独触发呼出。隐藏时用事件与单次计时器驱动。

| 事件 | 状态与动作 |
| --- | --- |
| 无按键按下的指针进入触发带 | 停留 70 ms 后开始显示。先画占位格，再异步填图。淡入 160 ms，缓出。首个可见帧提交后启用命中。 |
| 指针离开保留区 | 等待 180 ms，再以 180 ms 缓入淡出。等待时返回则取消隐藏，淡出中返回保留区则从当前透明度反向淡入。退场期间关闭缩略图命中。 |
| 淡出结束 | 隐藏绘制并撤销该窗口的缩略图订阅。保留最近使用的缓存。计时器和动画结束回调须核对本轮显隐请求，避免旧回调关掉已重新打开的条。 |
| 拖图、拖滚动条、主图手势进行中、文件拖放、菜单跟踪或模态框打开、窗口失活／最小化／关闭、幻灯片开始、原生全屏过渡 | 取消定时器和按压并立即隐藏。所有阻止条件解除后才按实时指针位置重新走 70 ms 判定。窗口关闭直接清理，不再触发恢复。 |
| 系统开启“减少动态效果” | 保留进入与离开延时，透明度直接切到目标值。系统设置变更可通过 `NSWorkspace` 通知同步。 [Apple AppKit 文档](https://developer.apple.com/documentation/appkit/nsworkspace/accessibilitydisplayshouldreducemotion?language=objc) |

- 单击邻居先校验目标文件，单击当前格不发起加载。校验及主图加载期间只处理一个缩略图跳转请求，保留旧中心并标记等待目标。同目录主图成功切换后，条以 180 ms 交叉淡入淡出重新居中。过渡期间暂停缩略图激活。常规解码失败沿用既有错误画面并隐藏条。缩略图仍在生成或生成失败时，对应文件只要仍可用就可显式打开。
- 只有无修饰键的主键按压从可交互格开始时，缩略图才接管本次序列。抬起仍须命中按下时同一文件，且目录快照仍有效。拖出格、超出系统拖动阈值、改绑、失去鼠标捕获或窗口失活均取消激活，已接管序列的抬起仍由该控件收尾。在格内识别到双击时只执行首次激活动作。空白处点击、修饰键点击和右键继续走原有映射，由主图开始的拖动也继续由主图收尾。面板内的滚轮和横向手势只平移缩略图，保留阶段及惯性的归属；面板外起始时沿用主图映射。
- 鼠标呼出时保留视口焦点。目录与空间符合显示条件时启用“聚焦缩略图”，菜单跟踪结束后激活，从当前格开始。左右键跳过空槽移动焦点，Enter 或 Space 打开焦点项。缩略图聚焦时为这些键和 Esc 接受 `ShortcutOverride`，并接入既有窗口 Esc 分发，在 Cocoa 全屏实测一次 Esc 只执行一个动作。Tab、Shift+Tab 退出到原焦点链，Esc 关闭条并还焦视口。键盘退出后，如果指针仍停在触发带内，等它移出触发带再回来才重新悬停打开。切图成功时焦点随所选文件到新中心，目录重排时尽量按文件恢复焦点，原项不可见时回到当前格。 [Qt 键盘事件](https://doc.qt.io/qt-6/qkeyevent.html) · [窗口 Esc 分发](../src/mainwindow.cpp)
- 两种绘制路径共用一组可操作的无障碍元素，暴露文件名、目录位置、当前状态和打开动作。元素的屏幕坐标和命中由同一逻辑布局换算，隐藏、失效和退场时同步撤销操作。键盘或 VoiceOver 主动进入时维持可见，退出或失活后回收。播报焦点和实际切图结果，单格像素就绪时保持安静。全屏下，仅在条可见且指针位于保留区时暂停光标隐藏计时，收起后恢复既有计时。 [Qt 无障碍接口](https://doc.qt.io/qt-6/qaccessibleinterface.html)

## 目录与切图状态

| 场景 | 绘制与交互 | 完成条件 |
| --- | --- | --- |
| 首次扫描或切换基目录 | 旧条立即收起，鼠标和键盘入口均不使用旧列表。以来源标记排除 URL 下载临时目录。 | 有新主图和包含它的有效快照后，按当前触发条件显示。两者可以任意顺序到达。 |
| 同目录失效后重扫 | 仍显示原主图时，可暂留中心和已画出的邻居作为不可操作的等待状态，取消按压。刷新期间退出仍可淡出。 | 新快照一次性替换布局和命中。当前图缺失、目录不足两项或扫描失败时收起。键盘焦点在有效结果发布后按文件恢复，窗口已失活时不抢回焦点。 |
| 已知文件版本的邻居被点击 | 后台检查仍是显示过的版本，目标格保留位置。文件已删除时使目录失效，版本变化时更新该格预览并等待再次点击。 | 校验成功且当前主图和目录快照仍匹配时，才提交主图请求。 |
| 尚未生成预览的邻居被点击 | 用该格原始路径解析目标并在校验时绑定其当前版本。缩略图解码成功与否不阻塞这一动作。 | 文件缺失则取消并刷新；版本校验通过后走普通主图加载。 |
| 验证过程中用户离开触发区，或从菜单、键盘、拖放发起其他打开 | 鼠标自然离开只影响显隐。替代打开、Esc 关闭已聚焦的条、目录版本变化或窗口失活／关闭会取消未提交的缩略图跳转。 | 过期校验结果不允许迟到切图。已提交的主图请求沿用原有请求生命周期。 |

文件版本核对有两个边界。首先在后台比较点击所见的文件版本与读取到的目标，再在主图读取前和结果提交前校验预期版本。沿用已有加载器时须为缩略图来源的请求携带预期版本，普通打开继续按既有逻辑处理文件变化。校验失败时保留旧图，结束等待标记，并通过现有轻量提示反馈目标已变化或不可用。快照失效或在 800 ms 内尚未验证成功时取消本次提交，允许再次点击。800 ms 是界面等待上限，阻塞的文件操作退出前仍占后台名额。基于元数据的检测覆盖可辨认的文件变更，无需为每次点击读整文件计算哈希。

## 接入现有代码

1. **目录快照。** `QVFileEnumerator` 提供过滤、排序及递归目录枚举。以 `QVImageCore` 发布的基目录、列表版本、`FileDetails::loadedIndexInFolder` 和当前文件状态为准。文件提交、列表发布、循环设置变化时只提取可见槽位。当前项沿用核心的路径匹配规则。各格保存列表原始路径及索引，供打开动作核对。路径或索引发生重用时，以列表版本和当前图共同判断这次绑定是否仍有效。 [目录枚举](../src/qvfileenumerator.cpp) · [文件与目录状态](../src/qvimagecore.cpp)
2. **目录失效。** 重命名、删除、撤销删除、导出和应用失活通过 `folderListingsInvalidated` 将列表标脏。将失效和跨目录请求开始及时通知视口，涵盖列表被清空到 `folderInfoChanged` 发出之间的时段。仅在条可见或有打开意图且快照已失效时，借用核心发起异步重扫。同基目录、同失效代次合并请求；扫描途中再次失效时，过期结果不能恢复旧格，完成后只刷新最新代次。每次悬停只校验可见项的文件版本。Finder 在应用保持前台时新增文件，列表在下一次目录刷新时纳入；首版不增加目录监听或轮询。 [应用目录失效通知](../src/qvapplication.cpp) · [文件操作](../src/mainwindow.cpp) · [核心刷新](../src/qvimagecore.cpp) · [URL 下载来源](../src/urldownload.cpp)
3. **精确切图。** 在 `QVImageCore` 提供缩略图专用的已校验目录项入口，与 `goToFile(Constant)` 共用指定项语义和忙碌保护。主线程通过目录版本、当前图、索引和原始路径做有界核对。现有 `goToFile()` 会调用 `QFile::exists()`，`loadFile()` 会遍历列表确认递归基目录，加载器也会同步查询文件身份。缩略图入口把该次校验所需的文件探测放入后台，使用已知列表项与基目录提交受版本约束的请求，复用解码、请求 ID、最近打开记录和 `postLoad()`。即使主图已缓存，也在后台核对预期版本再交付。目标版本失配单独结束等待，保持旧主图；可读目标的普通解码错误沿用既有错误处理。 [导航与加载](../src/qvimagecore.cpp) · [主图加载器](../src/qvimageloader.cpp) · [视口加载后处理](../src/qvgraphicsview.cpp)
4. **输入和生命周期。** `MainWindow` 持有每窗口的缩略图状态，接入现有事件过滤器和全屏完成回调。使用互相独立的阻止条件处理重叠场景，例如菜单结束时窗口仍失活。Cocoa 原生菜单跟踪也进入该状态，菜单命令请求聚焦时等菜单退场再执行。滚动或手势结束采用相应结束事件。缺少阶段的普通滚轮根据每次事件所在区域路由。关闭、最小化和原生过渡时清除命中、鼠标捕获与光标保持，应用重开只恢复悬停偏好。 [窗口事件](../src/mainwindow.cpp) · [Cocoa 桥接](../src/qvcocoafunctions.mm) · [AppKit 菜单跟踪](https://developer.apple.com/documentation/appkit/nsmenu/didbegintrackingnotification?language=objc)
5. **覆盖层与几何。** Qt 路径用视口子控件；原生 SDR/HDR 在 `navigationOverlayLayer` 下建独立子层。原生导航层与主图的亮度过渡容器分开，避免缩略图随 HDR 亮度淡变。两条路径共享逻辑坐标、按压状态和透明度，原生层只绘制。视口几何、滚动条、屏幕/DPR 和主题变更时发布同一份新布局给绘制和命中，视觉后端切换保留当前淡入淡出进度。若新后端尚未就绪，暂时撤销命中，绘制提交后再恢复。覆盖层放到与现有导航按钮相同的原生坐标转换中，像素对齐后中心误差不超过 1 pt。原生层以面板图像更新内容，切图过渡逐帧只改新旧层的透明度。 [原生导航覆盖层](../src/qvcocoafunctions.mm) · [视口几何](../src/qvgraphicsview.cpp)
6. **设置与菜单。** 在 `SettingsManager` 注册默认开启的悬停选项，通过 `ActionManager` 在系统和窗口菜单同步勾选。开关为应用级，关闭时立即收起由悬停打开的条，显式聚焦仍可用。聚焦命令只发给触发它的有效窗口，菜单退场后再确认目标窗口与目录仍有效。沿用现有翻译机制，覆盖菜单、提示和无障碍状态。现有 `QVImageCore::settingsUpdated()` 会重扫目录，实现时按实际枚举参数变化触发重扫，确保单独切换悬停不重扫、不重新预读主图。 [设置管理](../src/settingsmanager.cpp) · [菜单分发](../src/actionmanager.cpp) · [核心设置更新](../src/qvimagecore.cpp)

## 解码、缓存与性能预算

- **按需解码。** 条进入淡入状态时才提交任务，优先处理当前格和左右邻居。原生入口依据 ImageIO 元数据放行 JPEG、HEIF、PNG 和 TIFF，源像素上限为 6,400 万，请求子采样并限制预览长边。满足 8 倍子采样且样本深度为 1–8 位的 PNG 上限为 1 亿像素。其他普通原生格式上限为 800 万像素。Qt 仅在原生未能生成且允许回退时读取，按 64 MiB 临时缓冲估算限制栅格源。原生与 Qt 均在后台串行解码，输出按格宽高乘 DPR 等比约束。 [Apple Image I/O 缩略图](https://developer.apple.com/documentation/imageio/cgimagesourcecreatethumbnailatindex(_:_:_:)) · [Apple Image I/O 子采样](https://developer.apple.com/documentation/imageio/kcgimagesourcesubsamplefactor) · [Qt QImageReader](https://doc.qt.io/qt-6/qimagereader.html#setScaledSize)
- **格式与色彩。** 动图取第一帧，HDR 使用 SDR 预览。RAW 源像素上限为 6,400 万，使用与主图方向一致的 RAW 解码图生成 SDR 预览，优先采用草稿模式。小体积 SVG/SVGZ 直接按目标尺寸栅格化。EPS 文件上限为 16 MiB，复用受限的 Ghostscript 及 PDF 栅格化路径生成缩略图。统一缓存带 sRGB 标签的 8 位预乘 Alpha 图像。解码失败或超预算时显示格式占位，仍可显式打开。查看中的旋转、镜像、缩放属于主图状态。 [Apple RAW 预览](https://developer.apple.com/documentation/coreimage/cirawfilter/previewimage?language=objc)
- **慢盘与云文件。** 对已知网络卷、离线卷和未下载的云占位，悬停复用版本匹配的现成预览或显示占位，不自动读取图像内容。可读取后台元数据，用于版本判断。iCloud 下载状态仅用于能确认的 iCloud 项，其他文件提供程序状态未知时按可确认的卷和文件信息处理。用户显式打开时走现有主图访问路径。把有效性校验、格式占位和临时读取失败分开记录，避免短期失败缓存把文件永久标为不支持。 [SMB 枚举处理](../src/qvfileenumerator.cpp) · [Apple iCloud 文件状态](https://developer.apple.com/documentation/foundation/urlubiquitousitemdownloadingstatus)
- **缓存身份。** 应用级 LRU 以解码后的实际字节数计费，上限 24 MiB。缓存键由文件规范化路径、可用的文件 ID、大小、高精度修改时间、目标像素尺寸和解码策略版本组成。规范化沿用系统文件比较语义，目录项的原始路径与预览缓存分别保留，避免大小写、Unicode 或别名处理改变导航目标。工作线程在读前和读后复核文件版本，变化则丢弃并按新版本请求。重载增加该文件的预览版本，使同元数据的替换也能主动失效。同键合并，瞬时读取失败最多缓存 3 秒，仅在下次显现、重载或身份变化时重试。跨屏先沿用版本匹配的旧尺寸预览，再替换为新 DPR 的结果。
- **并发和回收。** 使用 `QvAsync` 的 Shared 队列及退出清理。纯预览任务低于目录扫描和相邻主图预读；全局最多提交 2 个纯预览任务，同时只允许 1 个可能全尺寸解码的任务。点击后的文件校验优先于纯预览任务，全局最多提交 1 个，且只保留仍有效的等待请求。调度器按窗口合并可见需求。窗口隐藏或改绑时撤销预览订阅，其他窗口仍订阅的同键任务继续。取消后已运行的同步工作仍计入名额，实际退出或排队闭包被清除才归还，归还不依赖 GUI 回调。投递前核对窗口存活、最新订阅、绑定文件版本和目标尺寸。原生副本和可见格持有的引用另外计量，收起时释放。以 2× DPR 的 144 × 104 pt、4 字节每像素计算，9 格一份像素数据为 2,106 KiB。后台校验和预览独立于主图 Foreground 队列，校验成功的显式请求沿用主图优先级。 [异步调度与退出](../src/asyncwork.cpp) · [取消与投递](../src/asyncwork.h) · [加载优先级](../src/qvimageloader.cpp)

## 验收与实施顺序

| 阶段 | 验收场景与通过条件 |
| --- | --- |
| 1. 槽位与目录导航 | 覆盖首尾、两图与单图、递归同名、392/488 pt 尺寸边界，以及循环算法用例。任何可见帧的中心误差 ≤ 1 pt，缩略图显隐前后主图缩放、视口范围和滚动位置一致。按住 B 时重扫、删除 B 或把 C 排到其旧槽，松手均不跳转。分别让主图与目录扫描先完成，确认旧条不会在跨目录请求后重现。 |
| 2. 输入与窗口状态 | 用可控时钟测 70/180 ms 延时、淡出反转、过期回调和 Esc 后悬停恢复。用真实 Cocoa 输入覆盖双击、带修饰键的点击、主图拖入底部、手势惯性、滚动条、AppKit 菜单及窗口失活重叠。每个序列只被一个控件处理，关闭或全屏过渡期间无幽灵命中，光标计时在离开后恢复。两个窗口切换悬停偏好后同步勾选，无新增目录扫描，重启后保留选项。 |
| 3. 文件校验与解码 | 模拟 B 在显示后被同路径替换、后台校验超时、校验成功后到解码前替换、已有主图缓存时替换。旧图仍居中，迟到回调无切图。模拟校验期间快捷键打开 C，C 提交后 B 不再生效。用慢盘、网络卷和云占位验证悬停与点击校验不阻塞窗口，已知离线占位不触发后台内容读取。覆盖 RAW 缺内嵌预览、损坏文件、像素尺寸溢出、EXIF 旋转、广色域透明图及动图首帧。用可控完成顺序测跨屏、关闭和改绑，同键跨窗去重，各类任务均按并发上限运行并归还名额。 |
| 4. 原生合成与无障碍 | 在 Cocoa 下跨 Qt、原生 SDR/HDR、1×/2×、跨屏、窗口缩放和原生全屏，检查边角合成、像素位置、命中和后端移交。使用 VoiceOver 和键盘验证聚焦、跳转、回焦及系统减少动态效果和透明度设置。两条绘制路径通过后再默认启用。 |

首轮性能目标在同一台 Apple Silicon Mac、同一批本地样本上对比。记录指针进带、淡入开始、占位首帧、超过半数有效格出现真实预览、点击校验起止、主图请求与提交、队列等待及峰值内存。每组至少 30 次，冷缓存清空应用缩略图缓存并注明系统文件缓存状态。快照已就绪时，从开始淡入到占位首帧 P95 ≤ 33 ms；本地普通 JPEG 从开始淡入到过半有效格出现预览 P95 ≤ 250 ms。以关闭悬停且条收起为对照，用同一个普通导航入口比较主图请求到提交的延迟，并行预览组的 P95 增幅 ≤ 10%。另报缩略图点击到提交的端到端延迟及校验超时率。比较 100 张与 10,000 张目录在快照发布后的每帧成本，区分目录扫描、窗口动画和解码。记录 Qt 与原生路径在 60/120 Hz 下的丢帧与像素上传次数。上述数值是实施后测量目标。 [仓库测试说明](../docs/TESTING.md)
